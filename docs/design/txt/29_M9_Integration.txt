29 – M9 Integration

Module design for the outward surface: the public API as a versioned OpenAPI contract
with scoped OAuth2 clients, journal export derived from the posting maps for the
accounting system to come, notification rules and templates with provider adapters, the
e-invoicing seam, and the webhook design held for phase 2. Adapters translate; they
never hold a business rule.

Two principles. An adapter is a translator, never a place for business rules: the posting map is M4's data, the invoice
snapshot is M4's document, the notification rule fires on another module's event – M9 only carries them outward in the
shape the outside world needs (doc 17 §10.2). And the public API exposes module commands and queries under the
same scope, permission and idempotency rules as the back office: a client is a principal, not a back door.

3.2 The public API

Aspect                     Design

Shape                      REST under /v1 (doc 17 §10.1): OpenAPI 3.1, bearer tokens, idempotency keys on mutations, cursor
                           pagination, problem details, ETags on documents. The bundle (doc 33) is assembled from the module slices; the
                           public subset is marked x-public: true and is the only part clients see.

Phase-1 public operations  Read: invoices, credit and debit notes, payment receipts (seller and buyer views through PARTY masking),
                           GRNs (own), stock balances (own), exposure and statements (own relationship side), journal exports (own),
                           customer accounts and postings (own MPCS, customers:read). Write: acknowledge a journal export; nothing
                           else in phase 1.

Versioning                 /v1 is stable for the phase; additive changes only; a breaking change opens /v2 with /v1 supported for at least
                           12 months and a Sunset header; deprecations listed in the bundle.

9. Non-functional design

Aspect             Design
9.1 Security
                   Clients are principals under the same scope filter and RLS; scopes never exceed the granting administrator's
9.2 Isolation      permissions; credentials hashed (secrets) or certificate-bound; rotation with overlap; rate limits at the edge and
9.3 Correctness    in-process; every write audited; the public subset is explicitly marked in the bundle.
9.4 Privacy
9.5 Compatibility  Adapters run in the worker profile with timeouts and circuit breakers; a provider outage never blocks a business
                   transaction (notifications are asynchronous by design).

                   Journal exports balance by construction; a map defect is an ALERT; exports are immutable and superseded,
                   never edited; hashes let the consumer verify a download.

                   Notification logs hash recipients and keep no bodies; customer channels require consent; the public API exposes
                   customer data only under customers:read to the owning MPCS.

                   Additive changes within /v1; 12-month deprecation; generated clients versioned with the bundle.
