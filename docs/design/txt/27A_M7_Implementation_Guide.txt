Everything the M7 developer needs: the customers schema as DDL, seed data, package
layout, the API slice, handler specifications with pseudocode for the four that matter
(reuse detection, the account-tender consumer, repayment allocation, anonymisation),
the customer snapshot, the till contracts for account tender and repayment, screens,
tests and tickets. Self-contained; restated material is marked.

Read this first. Two things must be right from the first commit: personal data never leaks into events, logs or
snapshots beyond what the till needs to serve the customer (name, phone, balance, limit), and the posting ledger is
insert-only with the balance as a recomputed cache. The privacy tests in Section 9 run in CI; a payload containing a
phone number or a NIC fails the build.

6.1 Reuse detection

ReuseDetector.check(phone, forCustomer?): Outcome

current = phones.currentPrimaryHolder(phone)                                       // valid_to IS NULL

if (current != null && current.customerId != forCustomer) return CONFLICT(current)                      // must

ChangePhone on the other customer first

recent = phones.holdersWithin(phone, config.reuseWindowMonths)                     // valid_to within the window

if (recent.isNotEmpty()) return NEEDS_CONFIRMATION(recent.map { it.customerId })                        // operator

confirms different person: name + NIC last4 when an account exists

return CLEAR

// on confirmation the command carries confirmedIdentity = true and the audit event records the previous

holders' ids (never their names)

6.2 Receipt tender consumer

@EventConsumer(types={"receipt.issued.v1","receipt.refunded.v1","receipt.voided.v1"}, consumer="m7.tenders")

for tender in bundle.tenders where kind == ACCOUNT:

acct = accounts.lock(tender.customerAccountId)                                     // FOR UPDATE

kind = when (event) { issued -> CHARGE; refunded, voided -> CREDIT }

amount = if (kind == CHARGE) tender.amount else -tender.amount

breach = kind == CHARGE && (acct.balance + amount > acct.creditLimit)

postings.insert(Posting(acct, kind, amount, businessDate = bundle.document.businessDate, document =

bundle.document.id, receiptNumber, location, operator,

                     offline = tender.offline, limitBreached = breach))

acct.balance += amount; accounts.save(acct)

if (breach) { audit REVIEW ACCOUNT_LIMIT_BREACH(offline = tender.offline); if (acct.hardBlock &&

tender.offline) audit ALERT HARD_BLOCK_BYPASSED_OFFLINE }

events.publish(kind == CHARGE ? AccountCharged : AccountCredited)

changeLog.record(locationsOf(acct.mpcs), "customer", acct.customerId, UPSERT) // balance to tills

(coalesced)

6.3 Allocator and 6.4 Anonymiser

Allocator.allocate(paymentPosting, mode, specific?):
    open = postings.openCharges(account) ordered by business_date, received_at // amount - allocated_amount >
           0
    remaining = payment.amount
    targets = if (mode == SPECIFIC) specific.map { charge(it.id) to it.amount } else open.map { it to
           min(it.open, remaining) }
    for (charge, amt) in targets while remaining > 0: a = min(amt, charge.open, remaining)
         allocations.insert(payment, charge, a); charge.allocated += a; payment.allocated += a; remaining -= a
    // remaining > 0 stays unallocated on the payment (credit balance); ageing uses charge.open and
           business_date

Anonymiser.apply(customer):
    require(accounts.noneOpenWithBalance(customer), "erasure.open_balance")
    customer.displayName = "Customer"; displayName_si/ta = null; nic_hash = null; nic_last4 = null; attributes =
           {}; status = ANONYMISED
    phones.closeAll(customer, reason = "ERASURE"); consents.withdrawAll(customer); tags.clear(customer)
    postings, allocations, payment documents: untouched (retention); statements object keys: deleted; audit
           records the request id only

CustomerSnapshotContributor: tables(): ["customer"]
    rowsFor(location): accounts of the owning MPCS with status OPEN or SUSPENDED (and the identity rows behind
           them) ->
        { customerId, displayName (shop language with fallback), phone (primary), language, accountId,
               creditLimit, balance, offlineCap, hardBlock, status, tags[] }

        (creditLimit - provisionalBalance) unless !hardBlock (warn);
