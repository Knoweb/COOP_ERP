29A – M9 Integration: Implementation Guide

Everything the M9 developer needs: the integration schema as DDL, seed data
(templates, rules handed over by the modules, providers, API scopes), package layout,
the admin and public API slices, handler specifications with pseudocode for client
registration, the journal builder and the notification adapters, the bundle assembly for
doc 33, screens, tests and tickets. Self-contained.

Date              9 September 2026
Prerequisite      Sprint 0 (identity, notifications delivery, attachments, scheduler); the module slices and posting maps of docs
                  21A–28A; M7 consent query
Estimated effort  About 15 developer-days plus 3 for the doc 33 bundle assembly
Restated content  Marked restated from doc X §Y.

Read this first. Nothing in this module decides anything about money, prices or documents. If you find yourself writing
a rule about when an invoice is due or which account a write-off hits, stop: that belongs in M4, M5 or M7's posting
map. M9 turns other modules' facts into the outside world's shapes and turns clients into principals the kernel already
knows how to police.

CREATE TABLE integration.api_scope (scope_code varchar(40) PRIMARY KEY, description_en text NOT NULL,

        permission_codes text[] NOT NULL, mpcs_only boolean NOT NULL DEFAULT false);
CREATE TABLE integration.api_client (client_id uuid PRIMARY KEY, owner_entity_id uuid NOT NULL, name text NOT

        NULL,
    kind text NOT NULL CHECK (kind IN ('ACCOUNTING','THIRD_PARTY','INTERNAL_TOOL')), credential_kind text NOT

           NULL CHECK (credential_kind IN ('SECRET','CERT')),
    provider_client_id text NOT NULL UNIQUE, cert_subject text, scopes text[] NOT NULL, rate_limit_per_minute

           int NOT NULL DEFAULT 600,
    status text NOT NULL DEFAULT 'ACTIVE' CHECK (status IN ('ACTIVE','SUSPENDED','REVOKED')), created_by uuid

           NOT NULL, created_at timestamptz NOT NULL DEFAULT now(),
    UNIQUE (owner_entity_id, name));
CREATE TABLE integration.api_credential_history (id uuid PRIMARY KEY, client_id uuid NOT NULL REFERENCES

        integration.api_client, secret_hash text, cert_subject text,
    valid_from timestamptz NOT NULL, valid_to timestamptz, rotated_by uuid NOT NULL, owner_entity_id uuid NOT

           NULL);
CREATE TABLE integration.api_call_log (call_id uuid NOT NULL, at timestamptz NOT NULL DEFAULT now(), client_id

        uuid NOT NULL, owner_entity_id uuid NOT NULL,
    operation text NOT NULL, status smallint NOT NULL, latency_ms int, rows int, PRIMARY KEY (at, call_id))

           PARTITION BY RANGE (at);

CREATE TABLE integration.posting_map_registry (doc_type_code varchar(8) NOT NULL, line_kind text NOT NULL,

side text NOT NULL, owner_module text NOT NULL,

debit_role text NOT NULL, credit_role text NOT NULL, amount_source text NOT NULL, PRIMARY KEY

(doc_type_code, line_kind, side)); -- union of M4/M5/M7 maps, registered at start

CREATE TABLE integration.journal_export (export_id uuid PRIMARY KEY, owner_entity_id uuid NOT NULL,

period_from date NOT NULL, period_to date NOT NULL,

format text NOT NULL CHECK (format IN ('JSON','CSV','ADAPTER')), provisional boolean NOT NULL DEFAULT false,

supplement_of uuid, generated_after timestamptz,

status text NOT NULL DEFAULT 'REQUESTED' CHECK (status IN

('REQUESTED','GENERATED','FAILED','ACKNOWLEDGED','SUPERSEDED')),

object_key text, line_count int, total_debit numeric(16,2), total_credit numeric(16,2), content_hash

char(64), generated_at timestamptz,

acknowledged_by text, acknowledged_at timestamptz, supersedes uuid, error text, requested_by uuid NOT NULL,

requested_at timestamptz NOT NULL DEFAULT now());

CREATE TABLE integration.journal_line (line_id uuid PRIMARY KEY, export_id uuid NOT NULL REFERENCES

integration.journal_export, seq int NOT NULL,

document_id uuid NOT NULL, doc_type_code varchar(8) NOT NULL, doc_number_display text NOT NULL, line_kind

text NOT NULL, side text NOT NULL,

debit_role text NOT NULL, credit_role text NOT NULL, amount numeric(14,2) NOT NULL CHECK (amount > 0),

business_date date NOT NULL,

counterparty_entity_id uuid, reference text, owner_entity_id uuid NOT NULL, UNIQUE (export_id, seq));

GRANT INSERT ON integration.journal_line TO app_rw;                                -- never updated

CREATE TABLE integration.notification_template (template_id varchar(48) PRIMARY KEY, owner_entity_id uuid,
       channel text NOT NULL CHECK (channel IN ('SMS','EMAIL','IN_APP')),

   subject_en text, subject_si text, subject_ta text, body_en text NOT NULL, body_si text, body_ta text,
          placeholders_schema jsonb NOT NULL,

   status text NOT NULL DEFAULT 'DRAFT' CHECK (status IN ('DRAFT','ACTIVE','RETIRED')), version int NOT NULL
          DEFAULT 1);

CREATE TABLE integration.notification_rule (rule_id uuid PRIMARY KEY, owner_entity_id uuid, event_type text
       NOT NULL, predicate jsonb, template_id varchar(48) NOT NULL REFERENCES integration.notification_template,

          ('ROLE_AT_COUNTERPARTY','ROLE_AT_OWNER','CUSTOMER','EXPLICIT')), audience_spec jsonb NOT NULL,

   channels text[] NOT NULL, priority smallint NOT NULL DEFAULT 100, status text NOT NULL DEFAULT 'DRAFT' CHECK
          (status IN ('DRAFT','ACTIVE','RETIRED')), name text NOT NULL);

CREATE TABLE integration.provider_config (channel text PRIMARY KEY, primary_provider text NOT NULL,
       secondary_provider text, credentials_ref text NOT NULL,

   status text NOT NULL DEFAULT 'NOT_SUBMITTED' CHECK (status IN

          ('NOT_SUBMITTED','PENDING','SUBMITTED','ACCEPTED','REJECTED')),
   provider_ref text, submitted_at timestamptz, response_key text, attempts smallint NOT NULL DEFAULT 0,

CREATE TABLE integration.webhook_subscription (subscription_id uuid PRIMARY KEY, client_id uuid NOT NULL,

6.2 JournalBuilder

JournalBuilder.build(export):

docs = documents.issuedIn(export.entity, export.periodFrom, export.periodTo, issuedAfter =

                     export.generatedAfter /* supplements */)

                     .filter { registry.hasMap(it.type, sideFor(it, export.entity)) }       // side: SELLER if entity

                     issued, BUYER if entity is counterparty

seq = 0; lines = []

for d in docs: for (lineKind, amounts) in amountsByLineKind(d):                             // GOODS (net, tax),

                     ADJUSTMENT, RECEIPT/REVERSAL, WRITE_OFF, ...

for m in registry.mapsFor(d.type, lineKind, side):                                          // one map row per

                     amount_source (net, tax, cost, applied)

                     amt = amounts[m.amountSource]; if (amt == 0) continue

                     lines += JournalLine(++seq, d, lineKind, side, m.debitRole, m.creditRole, amt, d.businessDate,

                     d.counterparty, referenceFor(d))

require(lines.sumOf(debit) == lines.sumOf(credit), "journal.unbalanced")                         // by construction; a

                     violation is a map defect -> FAILED + ALERT naming the document

write JSON and CSV (ExportWriter) to object storage; content_hash; export GENERATED with totals and

                     line_count; publish journal.generated.v1

// amount sources come from the owning modules' queries (M4 PostingQueries.postingsFor, M5

WriteOffQueries.valueFor, M7 PaymentQueries.amountFor) -

// M9 never recomputes an amount; it only places it between two roles.

6.3 Notification adapters and audience resolution

AudienceResolver.resolve(rule, event): Recipients

ROLE_AT_COUNTERPARTY -> users at event.counterpartyEntity holding role template audience_spec.role (M1

                     query), their emails / in-app ids

ROLE_AT_OWNER                        -> users at event.ownerEntity holding the role

CUSTOMER                             -> M7: customer of event.accountId; primary phone; require

                     consent(audience_spec.consent) else SUPPRESSED(reason = "no_consent")

EXPLICIT                             -> ids from the event payload field named in audience_spec.from_payload

HttpSmsAdapter.send(recipientHash, phone, body): POST to provider per a small per-gateway template {url, auth

header, body template, success matcher};

returns provider ref or throws; the kernel dispatcher handles retries, failover (secondary_provider) and the

                     log (doc 19 7)

SmtpEmailAdapter: JavaMail to the configured relay; InAppAdapter: inserts an in-app notification row read by

the shell's bell

ProviderHealthJob (hourly): a no-op auth call to each provider; failures -> ALERT; daily cap enforced by

counting today's SENT rows per channel

7. Assembling doc 33: the API bundle

tools/bundle-api.sh (BundleAssembler behind it)

1. collect backend/app/src/main/resources/openapi/*.yaml (hello excluded; m1party ... m9integration,

sync.yaml private, driver.yaml private)

2. validate: every slice parses (OpenAPI 3.1); operationIds unique across slices; shared components (Problem,

Money, Quantity, Cursor, Freshness,

                     DocumentRef, Scope) byte-identical to backend/app/src/main/resources/openapi/common.yaml;

                     security scheme = bearer (OIDC) everywhere;

                     every mutating operation declares Idempotency-Key; x-permission present on every operation and

                     matches @CommandHandler (17A check reused)

3. classify: x-public: true operations -> public bundle (knoweb-public-v1.yaml); everything else -> internal

bundle (knoweb-internal-v1.yaml);

                     sync and driver -> device bundle (knoweb-device-v1.yaml)

4. emit:             the three bundles; a CHANGELOG from the previous published version (added / deprecated

operations); the documentation site (redoc-class) for the public bundle;

                     regenerated typed clients (web from internal; an accounting-consumer client from public)

5. gate:             any deprecation without a Sunset date fails; any removed public operation fails unless the major

version changes

publish:             PublishApiBundle(version) stores the three files in object storage under

integration/api-bundles/<version>/ and records api_bundle.published.v1
