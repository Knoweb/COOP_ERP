## Dropped
- **M8-01** (stock position ordered by wall clock between sources): DROPPED. `stock.moved.v1` is published at central by M5 through `OutboxWriter` with `clock.instant()` (the central clock) as `occurredAt`; a till's clock never reaches `freshness` (M8 reads no till event for the stock position). The source is only the movement's numbering source (`LedgerService` line 133: device id or "central"), and the publish happens under the lot lock inside the movement transaction, so central's clock order matches the ledger order for one lot. Residual (low, not a finding): a central clock step backwards or two app nodes with skew could still misorder two sources; a lot-level ledger sequence would remove the dependency.
- **M1A-02** (temporary password stored in `kernel.idempotency_key.response_body`): DROPPED. `CredentialResetResult.temporaryPassword` is annotated `@JsonIgnore`; `CommandInterceptor` stores `mapper.writeValueAsString(result)` (line 137), which omits it, and a replay deserialises a result without the password (`UsersController:94` sets it from the live result only). The notification path hands it to `Notifications.send` parameters; `NotificationLog` stores no parameters. A test pinning "the stored body has no temporaryPassword" would be worthwhile but is not a defect.
