# CR-17A-2 — Spring Boot 3.3.x is out of support and carries critical vulnerabilities

- **Status:** raised
- **Date raised:** 2026-09-20
- **Raised by:** Claude Code session, while adding the vulnerability scan (branch `chore/repo-automation`)
- **Documents affected:** 17A §3 (toolchain and versions: "Spring Boot / Spring Modulith 3.3.x / 1.2.x"); doc 14 §3.1 if it restates the platform versions
- **Code affected:** `backend/build.gradle.kts` (Spring Boot 3.3.5), `backend/app/build.gradle.kts` (Spring Modulith 1.2.5), `.github/dependabot.yml` (which holds Spring Boot and Modulith on their current minor line because 17A says so)

## What is wrong or missing

17A §3 fixes "Spring Boot / Spring Modulith 3.3.x / 1.2.x". The build uses 3.3.5.

The first run of the vulnerability scan (Trivy over the CycloneDX bill of materials of the backend, 20 September 2026) reports, counting only findings that already have a fixed version: **7 CRITICAL and 31 HIGH**. By package:

| Package (brought in by Spring Boot 3.3.5) | Installed | Fixed from |
|---|---|---|
| `tomcat-embed-core` (21 advisories, 7 of them CRITICAL, CVE-2025-24813 among them) | 10.1.31 | 10.1.58 |
| `spring-core`, `spring-expression`, `spring-webmvc` | 6.1.14 | 6.2.11 to 6.2.19 |
| `spring-boot`, `spring-boot-starter-actuator`, `spring-data-commons` | 3.3.5 | 3.5.12 to 3.5.14 |
| `org.postgresql:postgresql` | 42.7.4 | 42.7.12 |
| `jackson-core`, `jackson-databind` | 2.17.2 | 2.18.8 |
| `micrometer-core` | 1.13.6 | 1.15.12 |

The Spring Boot 3.3 line no longer receives open-source releases. Its last patch releases cure part of the list (Tomcat, the PostgreSQL driver), but the fixes in Spring Framework itself exist only on the 6.2 line, which means Spring Boot 3.4 or 3.5. No patch release of 3.3.x can reach them.

## Why it matters

Nothing is deployed, so nobody is exposed today. But every module from M1 on is built on this base, and the system handles money, stock and personal data for the cooperative network. Moving a minor line of Spring Boot is cheap now (one template module, 81 unit and 21 integration tests, a smoke test, all automated) and dearer with every module added. It also removes a standing deviation: the build runs on Gradle 9.7.1, which the Spring Boot 3.3 plugin does not officially support and the 3.5 plugin does.

## Proposed change

**17A §3**, row "Spring Boot / Spring Modulith": replace "3.3.x / 1.2.x" with "3.5.x / 1.4.x (the current supported lines; move to the next supported line when this one leaves support, by change request)".

In the repository, as one pull request once this is accepted:

1. Spring Boot 3.3.5 to the latest 3.5.x, Spring Modulith 1.2.5 to the matching 1.4.x, and drop the Testcontainers version override if 3.5 manages a version that works with current Docker.
2. `.github/dependabot.yml`: hold Spring Boot and Modulith on the 3.5 and 1.4 lines instead of 3.3 and 1.2.
3. Run the whole pipeline; the `@Validated` handling and the `HandlerMethodValidationException` fallback in `RequestValidationHandler` were written against Spring 6.1 and are the places to look at first.

As an immediate step that needs no decision, because it stays inside "3.3.x": take the last 3.3 patch release. Dependabot proposes it by itself on its first Monday.

## Addendum, 20 September 2026: the web build tools, already moved

17A §3 also fixes "React / TypeScript / Vite 18 / 5.5 / 5". Vite 5 is out of support in the same way: the three open advisories on the dev server (one HIGH) are fixed from 6.4.2 and 6.4.3 only, and the CRITICAL advisory on Vitest from 3.2.6 only, with nothing on the 5.x and 1.x lines. Both are development tools and nothing of them ships, so the exposure was small; but S0-07 (the web shell) writes the first real web tests and the dev proxy, and would have written them against two unsupported tools.

The architect accepted the move on 20 September: Vite 5.4.21 to 6.4.3 (#26) and Vitest 1.6.1 to 4.1.11 (this follows it; Vitest 4 needs Vite 6, and only both together take Vite 5 out of the lock file). `pnpm audit` went from 7 findings (1 critical, 1 high) to 2 moderate, both in `react-router` 6, which S0-07 decides together with the routing it builds.

**17A §3**, row "React / TypeScript / Vite": replace "18 / 5.5 / 5" with "18 / 5.x / 6 (Vitest 4)". `.github/dependabot.yml` holds Vite on the 6 line from here.

## Impact if accepted

17A re-issued (together with CR-17A-1, as v0.2). One pull request in the repository. The weekly security scan then shows what is left, and the issue labelled `security` closes by itself when nothing CRITICAL or HIGH with a fix remains.
