# CR-28A-2 — Trade projections carry the document's location and are keyed by event; sales lines by line number; exposure from the current limit; exports audited

- **Status:** accepted (6 October 2026, on the architect's delegation; wave 2 code review); 28A not re-issued yet
- **Date raised:** 2026-10-06
- **Raised by:** Claude Code session, wave 2 code review decisions (`wave2-fixreview-m6-m8-m1admin.md` D4 to D7 and the amended fixes of M8-04, M8-06; `wave2-fixreview-rls.md` D-6), recorded in `docs/progress/deviations/2026-10-06-wave2-trading-projections.md`
- **Documents affected:** 28A §3 (the projection tables: `trade_document_fact` and its companions, `shop_sale_line_fact`, a new `credit_limit_fact`; "owner_entity_id and, where meaningful, location_id, with the four RLS classes"), §6 (the tile cache "per (tile, scope)"; the exposure view; the CSV export), §7 (the run worker); 21A §6 (ActivateRelationship publishes `credit_limit.changed.v1`, through CR-21A-7); doc 28 §1 (figures come from events) is the source and does not change
- **Code affected:** `m8reporting/V0007`; `TradeProjection`, `ShopSaleProjection`, `TradeSql`, `ExceptionQueue`, `TileSources`, `ReportSources`, `ReportQueriesImpl.CacheKey`, `ReportRunWorker`, `ProjectionStateStore`, `ReportCsv`

## What is wrong or missing

1. The five trade projection tables (m8 V0002, V0004) have no `location_id`; `own_read` tests the entity only. Kernel V0061 (27 September, doc 18 §3.7) decided that a shop-scoped session reads the documents of its shop only; a shop session holding `rpt.report.run` reads the entity's whole trading picture through the projections. 28A §3 says every reporting table carries `location_id` "where meaningful".
2. `trade_document_event` is keyed `(document_id, event_kind, owner_entity_id)` with `ON CONFLICT DO NOTHING`; a second dispute after a resolution, or a second settlement, is dropped.
3. `shop_sale_line_fact` is keyed by `line_id`, which the shipping till never sends, so every line of every real till receipt is skipped and "sales by item" is empty; the location is taken from the till's payload while M6 uses the device's shop.
4. The dashboard cache key omits the granted entities: two external auditors of one home entity share a cached dashboard.
5. The exposure view takes the limit from the latest warning and the threshold as the minimum ever warned; `RelationshipActivated` carries no limit, so a relationship whose limit was set at opening and never amended is never listed.
6. The CSV export writes no audit record; a report run whose read throws is dead-lettered instead of FAILED, because the read runs inside the dispatcher's transaction.

## Why it matters

A shop must see its own shop and only that (the rule the kernel already enforces for the documents); a society judges a shop by what sold, and that report is empty for real tills; a cached dashboard shared across grants is a tenancy breach.

## Proposed change

1. **28A §3**: `trade_document_event`, `trade_line_fact`, `trade_settlement_fact`, `trade_document_link`, `exposure_warning_event` carry a nullable `location_id`, the owner's location when the source document is at one (GRN, discrepancy, claim, claim return, delivery note), else NULL; `own_read`/`own_write` take the template's location line (`kernel.scope_location() IS NULL OR location_id = kernel.scope_location()`); `party_read` takes the template's form (CR-17A-3), the location line on the owner's side only. NULL rows are entity-level and are read entity-wide only. Tiles with no meaning for a shop (receivables, payables, exposure) are left out of a shop session's dashboard. Old rows stay NULL until the rebuild (28A `sys.projection.rebuild`, not yet built).
2. **28A §3**: `trade_document_event` is keyed by `event_id`; `(document_id, event_kind, owner_entity_id)` is a plain index; queries over kinds that can repeat take the latest by `(occurred_at, event_id)` or sum deliberately.
3. **28A §3**: `shop_sale_line_fact` is keyed by `(receipt_id, line_no)`; `line_id` is nullable; the location is the device's shop (the consumer's scope), the till's value only a fallback.
4. **28A §6**: the cache key is the whole visibility: class, entity, location, granted entities, whether a device is present, language and cost; "per (tile, scope)" means that.
5. **28A §3 and §6**: `reporting.credit_limit_fact (relationship_id, seller, buyer, credit_limit, effective_from, event_id)` fed by `credit_limit.changed.v1`, including the one `ActivateRelationship` publishes for the opening limit (CR-21A-7); the exposure view lists every relationship with a limit above zero against its current limit and reports the highest `trading.exposure_warn_thresholds` step the current ratio reaches; existing relationships are seeded by a one-off audited M1 publication.
6. **28A §6 and §7**: a CSV export writes `REPORT_EXPORTED` (report id, parameters, row count; no row content); screen reads are not audited; `reporting.max_period_days` (366) and `reporting.max_rows` (10,000) bound every report, the row cap in SQL; the run worker reads and renders in its own read-only transaction and records FAILED in the outer one; `last_event_at` is `least(event occurredAt, now())`.

## Impact if accepted

- **Documents**: 28A re-issued (§3, §6, §7); 21A through CR-21A-7.
- **Code**: `m8reporting/V0007` (columns, keys, the new table); the consumers and queries above; two configuration items.
- **Tests**: `RlsMatrixIntegrationTest` and `OwnPoliciesTestTheClassIntegrationTest` for the six tables with the location cases; a shop session sees its GRN and not the entity's invoices; two EXTERNAL scopes of one home entity get different dashboards inside the cache window; a till receipt without `line_id` yields its lines; a dispute after a resolution is kept; a run whose read throws ends FAILED.
- **Rejected**: a guard in `TileSources`/`ReportSources` (application code filtering by tenant); `scope_location() IS NULL` on the whole PARTY branch (differs from the kernel's own policy shape); a per-document sequence column; reading `RelationshipQueries` at query time (doc 28 §1); the user id in the cache key (no policy is per user).
