# CR-19A-4 — The sync paths break three rules the build enforces on every OpenAPI slice

- **Status:** accepted as revised
- **Decided 27 Sep 2026:** accepted as revised (PR #TBD), on the architect's delegation — not the exemption this CR proposed, but a shape that needs none. `openapi/sync.yaml` (K-08) puts every path under `/v1/sync/...` (not doc 32's `/sync/v1/...`), so the one rule "everything under `/v1` needs a token" already covers the till and `OpenApiSliceRulesTest`'s path check is never in tension with it. Every mutating operation carries a real `Idempotency-Key` parameter (the till sends its `batch_id` or a fresh UUID; the effect is idempotent by database state, doc 32 S3), so the header rule needs no exception either. Every operation carries `x-permission`, but not a permission of the catalogue a role could hold: device operations carry the marker `sync.device` (and the enrolment exchange `sync.enrolment_code`, `issueEnrolmentCode` the ordinary catalogue permission `sys.device.enrol`), read and enforced by `DeviceAuth`/`SyncController`, not by `PermissionResolver`. `tools/check-slices.mjs` and `tools/check-permissions.mjs` were checked directly: `check-slices.mjs` only requires that `x-permission` and `Idempotency-Key` be *present*, and `check-permissions.mjs` only checks that a `@CommandHandler`'s permission matches some operation's `x-permission`, never the reverse — so both pass sync.yaml today with no special case, no exemption and no scaffolding the till has to carry. No tooling change is made by this pull request, because none is needed; a case for this shape was still added to `tools/checks.test.mjs`, so the treatment is asserted rather than merely observed. Reason: an explicit `x-auth: device` exemption (this CR's original proposal) would still have required the build to special-case one slice forever; naming the device marker as an ordinary-looking `x-permission` value and moving the paths under `/v1/` costs nothing more to build and needs no standing exception to maintain. 17A, 19A and AGENTS.md are not re-issued by this pull request; a re-issue should describe this convention (`/v1/sync/...`, a device marker value of `x-permission` rather than a catalogue permission, ordinary `Idempotency-Key`) rather than CR-19A-4's original `x-auth: device` proposal.

## What is wrong or missing

19A §8 defines `POST /sync/v1/devices/{id}/enrol`, `POST /sync/v1/devices/{id}/batches`, `GET /sync/v1/locations/{id}/snapshot`, `POST /sync/v1/devices/{id}/heartbeat` and `POST /sync/v1/attachments/presign`. `OpenApiSliceRulesTest` fails a slice for:

1. a path not under `/v1/` ("every path is versioned under /v1/ (doc 17)"): these are under `/sync/v1/`;
2. an operation without `x-permission` ("every operation names the permission it needs"): a device is not a user and holds no permission from M1's catalogue; 19A authorises it by its device token (line 483: "auth: device token ACTIVE");
3. a mutating operation without the `Idempotency-Key` header: a batch is deduplicated by the device's sequence (409 on a sequence mismatch), which is stronger than a key.

So the day K-08 adds `sync.yaml` the build fails, and the cheapest way to make it pass is a permission that means nothing and a header nobody reads.

## Why it matters

The rules are right for user commands and wrong for a device protocol, and no document says so. Left alone, K-08 either weakens the rules for everybody or decorates the sync slice with fields that mean nothing, which the till then has to send.

## Proposed change

State the exception once, and have the build check it instead of trusting it.

- **17A and AGENTS.md:** "Slices are user-facing (`/v1/...`, `x-permission`, `Idempotency-Key`), except the device protocol `openapi/sync.yaml`, which is `/sync/v1/...`, authorised by device token and deduplicated by device sequence (doc 32)."
- **19A §8:** every sync operation carries `x-auth: device`. The slice rules accept `x-auth: device` in `sync.yaml` only, require it on every operation there, and require the path prefix `/sync/v1/` with it.
- `presign` stays in this slice only if tills alone call it; if the web client calls it too, it gets a second, ordinary operation under `/v1/`.

## Impact if accepted

17A and 19A re-issued with one paragraph each; one sentence of AGENTS.md. In K-08, `OpenApiSliceRulesTest` gains the device branch and a test that it bites.
