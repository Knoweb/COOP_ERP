# CR-19A-4 — The sync paths break three rules the build enforces on every OpenAPI slice

- **Status:** raised
- **Date raised:** 2026-09-21
- **Raised by:** Claude Code session, while preparing the 19A phase (branch `chore/19a-kernel-prep`, pull request #61)
- **Documents affected:** 19A §8 (lines 466–483, `openapi/sync.yaml`); doc 32 §3; 17A (the slice rules); AGENTS.md ("Every mutating operation carries an `Idempotency-Key` and an `x-permission` in its OpenAPI slice")
- **Code affected:** `OpenApiSliceRulesTest`, `tools/check-permissions.mjs`, from the day K-08 adds `openapi/sync.yaml`

## What is wrong or missing

19A §8 defines `POST /sync/v1/devices/{id}/enrol`, `POST /sync/v1/devices/{id}/batches`, `GET /sync/v1/locations/{id}/snapshot`, `POST /sync/v1/devices/{id}/heartbeat` and `POST /sync/v1/attachments/presign`. `OpenApiSliceRulesTest` fails a slice for:

1. a path not under `/v1/` ("every path is versioned under /v1/ (doc 17)"): these are under `/sync/v1/`;
2. an operation without `x-permission` ("every operation names the permission it needs"): a device is not a user and holds no permission from M1's catalogue; 19A authorises it by its device token (line 483: "auth: device token ACTIVE");
3. a mutating operation without the `Idempotency-Key` header: a batch is deduplicated by the device's sequence (409 on a sequence mismatch), which is stronger than a key.

So the day K-08 adds `sync.yaml` the build fails, and the cheapest way to make it pass is a permission that means nothing and a header nobody reads.

## Why it matters

The rules are right for user commands and wrong for a device protocol, and no document says so. Left alone, K-08 either weakens the rules for everybody or decorates the sync slice with fields that mean nothing, which the till then has to send.

## Proposed change

State the exception once, and have the build check it instead of trusting it.

- **17A and AGENTS.md:** "Slices are user-facing (`/v1/...`, `x-permission`, `Idempotency-Key`), except the device protocol `openapi/sync.yaml`, which is `/sync/v1/...`, authorised by device token and deduplicated by device sequence (doc 32)."
- **19A §8:** every sync operation carries `x-auth: device`. The slice rules accept `x-auth: device` in `sync.yaml` only, require it on every operation there, and require the path prefix `/sync/v1/` with it.
- `presign` stays in this slice only if tills alone call it; if the web client calls it too, it gets a second, ordinary operation under `/v1/`.

## Impact if accepted

17A and 19A re-issued with one paragraph each; one sentence of AGENTS.md. In K-08, `OpenApiSliceRulesTest` gains the device branch and a test that it bites.
