# CR-23A-1 — Pricing rules: no free goods through a price, a bounded backdate for control prices, the markdown's batch, Federation-only ceilings in SQL

- **Status:** accepted (6 October 2026, on the architect's delegation; wave 2 code review); the documents are not re-issued yet
- **Date raised:** 2026-10-06
- **Raised by:** Claude Code session, wave 2 code review decisions (`wave2-fixreview-m5-m3.md` M3-01, M3-02, M3-03, M3-07; `wave2-fixreview-rls.md` RLS-04, RLS-05; `wave2-fixreview-till-web-kernel.md` TWK-13), recorded in `docs/progress/deviations/2026-10-06-wave2-pricing-rules.md`
- **Documents affected:** 23A §3 (DDL and policies of `control_price`, `price_list`, `price_list_line`; the rule vocabulary's `checkBenefit`), §6 (EnterControlPrice, CreatePriceList/AuthoringValidator, the shared engine's candidate and markdown rules), §7 (configuration items); doc 23 §3.5 ("EXPIRY_MARKDOWN applies only to the specific batch") is the source and does not change
- **Code affected:** `m3pricing/V0006`; `shared-engine` (`RuleEvaluator`, `PriceResolver`, `RuleVocabulary`, `ENGINE_VERSION`); `EnterControlPriceHandler`, `AuthoringValidator`, `openapi/m3pricing.yaml`; `seed/kernel/config-items.yaml`

## What is wrong or missing

1. `FIXED_PRICE 0` and `PERCENT_OFF 100` are accepted at authoring, and a RETAIL list line may be saved at 0.00: an item becomes free through a price, outside the write-off controls (two signatures, witness, value bands) that doc 25 puts on giving goods away.
2. `EnterControlPrice` accepts any `effectiveFrom`, including the past, and rewrites the superseded row's `effective_to` with no audit of the old value; `RescindControlPrice` refuses the past. A gazette price order takes effect on publication, usually before the steward enters it.
3. The engine evaluates the expiry markdown on `r.batch`, which under AUTO_LOWEST is the lowest-MRP candidate, not the unit sold; `DAYS.between <= D` is true for negative days, so an expired batch takes the markdown; the receipt line stamps that batch, so M5 depletes the wrong lot.
4. `own_write`/`own_update` on `pricing.control_price` admit any OWN entity, and `ceilingFor` selects by SKU with no owner filter: a society's row is a ceiling for every till, and the Federation's own entry is then refused by the exclusion constraint. `advisory_read` admits any entity's ADVISORY list. `buyer_read` on `price_list` admits SUSPENDED and REPLACED relationships.

## Why it matters

A till that sells at Rs 0.00 because a clerk forgot a cell is a stock loss with a receipt; a ceiling recorded later than the law says understates overcharges in compliance reports; a markdown on the wrong batch drifts the per-batch book and makes expiry write-offs wrong; a ceiling anyone can write is not a ceiling.

## Proposed change

- **23A §3 (rule vocabulary)**: `FIXED_PRICE > 0`; `PERCENT_OFF < 100`; a fixed price at or above the current list price warns at activation. A RETAIL `price_list_line.price` is `> 0` (`exclusiveMinimum: 0` in the slice and a `price_zero` guard, because a job or a till could set lines without HTTP). A free or promotional item is a FREE_ITEM rule or a DONATION/SAMPLES write-off.
- **23A §6 EnterControlPrice**: `effectiveFrom` may be up to `pricing.control_price_backdate_days` (FEDERATION item, default 7; §7) before the business date; older is refused (`m3.control_price.effective_from_past`); an entry with `effectiveFrom < today` is a REVIEW audit `CONTROL_PRICE_RETROSPECTIVE` carrying the superseded row's previous `effective_to` in `before`. The table is the effective-time history; the audit row is the knowledge time.
- **23A §6 (the engine)**: a pricing candidate is a lot with `onHand > 0` and `expiry == null || expiry >= businessDate`; EXPIRY_MARKDOWN is evaluated on the identified batch (BARCODE_RESOLVED scan or PICKER pick), else the FEFO-first in-date candidate, matches only when `0 <= days <= D`, and stamps that batch on the line while `mrpApplied` stays the policy's MRP; a line rule with zero benefit is dropped before precedence (`PRIORITY_THEN_BEST` over the rest); `ENGINE_VERSION` 0.2.0.
- **23A §3 (policies)**: `control_price` `own_write`/`own_update` add `owner_entity_id = kernel.system_entity()`; `everyone_reads` admits the Federation's rows only; `advisory_read` on the two list tables admits the Federation's PUBLISHED ADVISORY lists only; `buyer_read` on `price_list` requires `r.status = 'ACTIVE'`. `mrp_policy` is unchanged (keyed by owner; the society's manager sets it).

## Impact if accepted

- **Documents**: 23A re-issued (§3, §6, §7). Doc 23 unchanged (its §3.5 is what the engine now does).
- **Code**: `m3pricing/V0006`; the engine (and the till ships the same version); the two handlers; the slice; one configuration item. Existing zero lines, if any, are corrected by a new list version, never edited; the rule seeds and the demo rules are checked for 0 and 100.
- **Tests**: engine unit tests for the batch and the day bounds; `RlsMatrixIntegrationTest` takes `federationRowsOnly` for `control_price` plus an M3 test of the Federation's row read by every class but NONE; a backdate inside and outside the window; a zero price refused in the slice and in the guard.
- **Rejected**: zero with a second approval (duplicates the write-off controls); refusing every past control-price date (records a ceiling later than the law says) or allowing any (rewrites history silently); markdown only when a batch is scanned (most packs carry a GTIN without a batch); admitting SUSPENDED buyers to the live list (the invoice is the record of the price charged).
