# CR-<doc>-<n> — Short title

- **Status:** raised | accepted | rejected | applied (document re-issued at vX.Y)
- **Date raised:** YYYY-MM-DD
- **Raised by:** name (person or the tool session and the ticket being worked)
- **Documents affected:** for example `24A §3.2`, `18 Part C`, `05 FR-POS-050`
- **Code affected:** module and package, or "none yet"

## What is wrong or missing

State the contradiction, gap or error precisely. Quote the sentences from the documents (from the `txt/` extracts) that conflict, with document and section.

## Why it matters

What breaks, or what cannot be built, if it stays as written. If code was already written to an assumption, say which `docs/DECISIONS_PENDING.md` id or comment it cites.

## Proposed change

The replacement wording or rule, per document and section. Keep it small enough to apply as one revision of each affected document.

## Impact if accepted

Which documents are re-issued (and their new versions), which code changes, which tests change. Nothing is applied to code until the status is **accepted**; the same problem exists in the documents and in other modules, so it is fixed there first.
