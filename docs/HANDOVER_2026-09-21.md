## 2. Do this before your next commit

1. **Update and reinstall.** The web tools changed major versions (Vite 6, Vitest 4) and the backend changed Spring Boot line.
   ```bash
   git checkout main && git pull
   cd web && corepack enable && pnpm install && cd ..
   make reset && make up
   ```
   `make reset` deletes your local database and volumes. Do it once: the web container keeps its `node_modules` in a volume, and the old one holds the old tools. You need Node 24, pnpm 12.4.2 (corepack takes it from `package.json`), Java 21 and Docker.
   **Done when:** `make up` ends by printing the addresses and the three dev logins.
2. **Your old branches.** 24 merged branches were deleted on GitHub. Run `git fetch --prune`. A local branch you still need is untouched; rebase it on `main` before you continue, because the formatter and the build rules below will otherwise surprise you at the pull request.
3. **Know the new rules of a pull request.** They are in `AGENTS.md` and `.github/pull_request_template.md`; the ones that will stop you on day one:
   - The **title is a conventional commit** (`feat(m1party): ...`, `fix(web): ...`). The repository squash-merges, so the title becomes the commit on `main`. A check fails otherwise.
   - **Java is formatted by the build.** `make format` formats the files you changed; `make test` fails on an unformatted one. Nothing else is reformatted, so your diff stays yours.
   - **The shape of a request lives in the OpenAPI slice**, not in the handler (`required`, `maxLength`, `format` ...). The kernel answers 400 `request.invalid` by itself. A handler guards business rules only. `backend/app/src/main/java/lk/coopfed/knoweb/hello/README.md` is the worked example.
   - **Do not merge on red.** Branch protection is not possible on the current GitHub plan, so the pipeline informs and cannot block yet. The architect will enforce it when the plan allows.
   - `make hooks` (optional) runs the quick checks before every `git push`.

Each step says what proves it worked. If a step fails on a clean `main`, that is a defect: open an issue, do not work around it.

| # | Do | You should see |

Addresses: web `localhost:5173`, API `localhost:8080` (`/actuator/health`), Keycloak `localhost:8085` (admin / admin), RabbitMQ `localhost:15672`, MinIO `localhost:9001`, Mailpit `localhost:8025`, PostgreSQL `localhost:5434`. `make up` prints them with the passwords.

**What you cannot test yet, so that nobody reports it as a defect:**

- **The server checks no permission.** The web client hides what a role may not do; a direct API call still succeeds. The permission resolver is kernel ticket K-03.
- **The backend does not read the login token yet.** The web client sends the scope in development headers, which the backend trusts. K-02 replaces both sides.
- **Audit entries and events are logged, not stored.** The tables arrive with K-04 and K-05.
- **Idempotency holds for one instance.** With two instances, a retry that reaches the other one is not recognised (K-03a). `make smoke TWO=1` skips that check and says so.
- **The till** builds and has screens, and is not connected to anything (section 6).

## 7. Things that cost time this weekend

- **A test run that sits still for twenty minutes** on Windows is usually Docker Desktop, not the tests: `docker ps` hangs too. Quit Docker Desktop, run `wsl --shutdown`, start it again.
- **On Linux, `pnpm install` failing with "Permission denied" in `web/node_modules`** was Docker creating that folder as root. Fixed in #60 (`make up` creates it first); if you have an old root-owned folder, delete it once with `sudo`.
- **A green check on an old pull request proves little.** Two Dependabot pull requests were green from runs older than most of the code. Rebase (`@dependabot rebase`) before you trust it.
- **A broken workflow file shows no failed check; it shows no checks at all.** `make lint-ci` before pushing a change under `.github/workflows/`.
- **Tomcat 10.1.58, which the advisories name as the fixed version, was never published.** Check that a version exists (`repo1.maven.org`, not the search index, which lags by months) before you put it in a build file.
