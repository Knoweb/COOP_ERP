- **K-06 internationalisation, part 1 (25 Sep, branch `feat/k-06-i18n`, on top of K-09).** Doc 19 section 5 as 19A section 6 restates it, without the A4 renderer (part 2, below). **Messages**: `IcuMessages` replaces the 17A stub on `java.text.MessageFormat` with ICU MessageFormat, the same three catalogues, positional arguments as before and now plurals, selects and named arguments (one Map); numbers inside a message in Western Arabic digits in every language (DR-6, the LATN numbering system on the format's locale). `Messages.text` returns `Text(value, fallback)`: an id the requested language lacks comes in English with the flag, and `ProblemResponses` puts `"fallback": true` on the problem document so the web shell can show its EN mark; a language the catalogue does not have (German) gets English without the flag, because that is not a missing translation; an id no language has comes back as the id and is logged. **Normalisation**: `TextNormaliser.nfc` (NFC and strip) and `NfcConverter`, a JPA converter applied to every String attribute automatically, so the write boundary is NFC without a module doing anything; a handler that writes through JDBC calls the normaliser. **Formats**: `Formats` (`IcuFormats`): money `1,234.00` and `Rs 1,234.00` (`රු.` and `ரூ.` for the other two), quantities to three decimals, `dd/MM/yyyy`, `dd/MM/yyyy HH:mm` in the business zone, LATN digits whatever the locale. **Collation and search**: `SearchSupport.orderByDisplayLanguage(column, locale)` gives the ORDER BY on the display language's column and ICU collation with English as the tie breaker; `matchAnyLanguage` and `pattern` give the three-column ILIKE the trigram indexes serve, NFC and escaped. **Test set**: `i18n/sort-test-set.yaml`, the curated Sinhala, Tamil and English names with their known order and the equivalent-spelling pairs, run on every build against the baseline collations (`CollationPostgresIntegrationTest`), meant to grow with the steward's findings. **Proof**: `IcuMessagesTest` (language, fallback with and without the mark, plurals, named arguments, LATN digits, broken and missing files stop the start), `FormatsAndSearchTest`, `CollationPostgresIntegrationTest` (the set sorts as listed under `kernel.si_icu`, `ta_icu`, `en_icu`; equivalent spellings are one name once normalised; text posted through the hello handler reaches the table in NFC). **Part 2, for the architect**: the A4 renderer (Thymeleaf to PDF through a headless Chromium worker with bundled Noto fonts, DR-3) needs two decisions before code: which font files are bundled and where (the web client takes them from npm; the backend has none), and whether the worker image carries Chromium (the pipeline installs it for the web e2e only). Until then every printed document is M4's to render. Decided 27 Sep 2026: the renderer is kernel ticket K-06b, due before M3-10, not M4, with the three Noto families of the web client bundled as backend resources and Chromium in the worker image only (PR #145, `docs/PLAN_TO_M2.md` 6.13), on the architect's delegation. 23A names "A4Renderer for labels" and M3-10's label job prints through it, and M3 comes before M4; M1 and M2 print nothing. `CR-19A-8` item 7.
