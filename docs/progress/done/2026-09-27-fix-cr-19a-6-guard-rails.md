- **CR-19A-6 guard rails for internal commands (27 Sep, branch `fix/cr-19a-6-guard-rails`, pull request #138).** Decided on the architect's delegation: `CommandHandler.INTERNAL` stays as M2-05 (#135) built it (doc 22 sections 3.7 and 4.3, 22A section 4 and 24A section 6.1 call RegisterBatch as an internal command inside the GRN transaction), and it is now enforced; CR-19A-6 is accepted with these rails. A review of main found four gaps: the interceptor's "requires the caller's transaction" test never fired (`TransactionOrderConfig` puts the handler's own `@Transactional` outside the interceptor, so a transaction is always active), so a controller or job calling `BatchRegistration` ran with no permission check and no idempotency; nothing stopped a public handler being marked internal; any module allowed `m2catalogue::api`, a web package included, could call it; and an operation with `x-permission: internal` was not refused. **Run time** (`kernel.internal.CommandInterceptor`, 19A section 3): every ordinary command runs with a thread-bound record of itself (handler, permission, the idempotency key it claimed), set around the handler in each branch (HTTP, and a job, consumer or sync call without a request) and cleared in `finally`; an internal command runs only while one is present and otherwise throws an `IllegalStateException` naming CR-19A-6; an ordinary command called while one is present throws a "nested command" `IllegalStateException` instead of the idempotency conflict it met before. No code path nests ordinary commands: the unit suite and the kernel, m1party, m2catalogue and hello integration tests pass with the refusal on. **Build time** (`ArchitectureTests`, each with a bite fixture under `archfixtures`): no class of a `web` package may use an internal handler, the api interface it implements or that interface's command record; an internal handler implements an interface of its own module's `api` package; only `@CommandHandler` classes may call that interface or the handler. **`tools/check-permissions.mjs`**: accepts `CommandHandler.INTERNAL` and a quoted code only (a constant or an expression is refused, since it would escape the slice comparison; `"internal"` as a string is refused in favour of the constant), and refuses an operation whose `x-permission` is `internal`; its logic is exported and tested in `tools/checks.test.mjs`. **Tests**: `testsupport.OuterCommand` (a test command that runs a body, imported by `PostgresIntegrationTest`) carries every RegisterBatch call of `BatchHandlersPostgresIntegrationTest`; the new `InternalCommandInterceptorPostgresIntegrationTest` (RegisterBatch in a bare transaction and with none refused; a GRN-like test command reached over HTTP registers the batch with exactly one idempotency row and one audit and event; its replay with the same key answers the stored result without running again; an ordinary command inside another refused as nested). No migration; `make reset` not needed. **Proof**: the unit suite with ArchitectureTests and ArchitectureRulesBiteTest, `node --test tools/checks.test.mjs`, `node tools/check-permissions.mjs`, and the kernel, m2catalogue, m1party and hello integration tests.
