- **Faster pull request pipeline (26 Sep, branch `ci/faster-pull-requests`).** From the CI timing analysis of 26 Sep. On a pull request `package` no longer waits for build-verify-test (on main `package-main` runs the same steps, a YAML anchor, after a green build-verify-test; the pull request check keeps the name "Package") and skips `make image`, which stack-smoke already builds and runs; the old build-verify-test is two jobs, `build-verify` (compile, generated files, unit tests, web) and `integration-test`, each about half of the old one, so a pull request answers in the time of the longer half; integration tests run in the forks that `COOP_ERP_INTEGRATION_FORKS` names (two on a laptop, one PostgreSQL container per fork, no shared ports or state; one in the pipeline, where two forks on the two-core runner were slower than one); `make test-scaffold` runs the copy's own tests, the architecture and slice rules and the schema, own-policy and runtime-role integration tests instead of the whole suite, which the nightly run now does on the copy (`SCAFFOLD_TESTS`); `backend/gradle.properties` turns on parallel builds, the build cache and a 2 GB heap; `check-generated` in the pipeline reuses the up-to-date `:app:test` (`ARCH_TESTS`); pnpm is set up before setup-node, which caches the pnpm store; the till job runs its steps only when `till/**`, `backend/shared-engine/**` or ci.yml changed and reports success otherwise. **Deviations:** none of a guide; the scaffolder proof on a pull request is narrower than S0-13 states, the whole proof moves to the nightly run.
