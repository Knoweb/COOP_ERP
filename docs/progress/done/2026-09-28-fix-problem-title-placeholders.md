- **Problem titles fill their placeholders (28 Sep, branch `fix/problem-title-placeholders`, found by the M8 lane).** `ProblemResponses.toProblem` formatted the title with no arguments, so a problem whose en/si/ta text has a named ICU placeholder (`report.template_unknown` `{templateId}`, `report.too_large` `{size}`/`{maxBytes}`, `report.timeout` `{seconds}`) threw inside the exception handler and the client received no `code`. It now passes the `ProblemException` parameters (the `Map` form `IcuMessages` already accepts for named arguments); no detail is formatted. **Proof**: `ProblemResponsesTest` (status, code, params and the filled title in all three languages, one and several placeholders; a problem without parameters still answers). M8 (#172) had removed placeholders from its problem texts to avoid the bug: `m8.report.unknown` gets `{reportId}` back in en/si/ta (a readable report slug from the URL, the same shape as `report.template_unknown`), and `ReportingHttpPostgresIntegrationTest` checks the filled title; `m8.run.not_found` (an internal run id) and `m8.run.language_invalid` (already lists the allowed languages) read better without one and stay as they are.
