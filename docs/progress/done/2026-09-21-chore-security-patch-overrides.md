- **The two security patches ahead of Spring Boot (21 Sep, branch `chore/security-patch-overrides`).** Decided by the architect on 21 September: take both. The catalogue gained `tomcat = "10.1.60"` and `postgresql = "42.7.12"`, and `app/build.gradle.kts` sets Spring Boot's `tomcat.version` and `postgresql.version` from them. **Tomcat 10.1.58, the version the advisories name, was never published** (Maven Central goes 10.1.57, 10.1.59, 10.1.60), so the override takes 10.1.60, the current patch release. An override that Spring Boot has caught up with holds a library back, so the new task `checkVersionOverrides` (part of `check`, so part of `make test`) reads the versions out of Spring Boot's own bill of materials and fails the build when an override is no longer ahead of it; proven by setting the override to 10.1.55, which fails with the instruction to delete it. The Dependabot pull request that brings the Boot patch carrying these versions will therefore go red until the two entries are deleted: that is the intent. Verified: `gradlew check` (81 unit tests, architecture rules, Spotless, the guard), `make test-int` (28), `dependencyInsight` shows 10.1.60 and 42.7.12 on the runtime classpath. **The scan of the backend is now 0 CRITICAL and 0 HIGH** (from 3 and 1; from 6 and 25 before CR-17A-2). Stack smoke, the two-instance run and the Playwright tests were left to this pull request's pipeline.
