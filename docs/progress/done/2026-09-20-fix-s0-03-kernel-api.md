- **S0-03 close-out: kernel API and stubs (20 Sep, branch `fix/s0-03-kernel-api`).** Review against 17A section 4.3 and 19A. Two defects in the message stub: a language the catalogue does not have (a browser set to German) got the message id as the text, and a catalogue file that could not be parsed was swallowed and every message of that language became its id. `JsonMessages` now reads the three files at start and refuses to start on a missing or broken one; an unknown language, and an id one language lacks, fall back to English. Two interface changes decided by the architect while nothing uses them: `kernel.api.BusinessClock` is gone and `java.time.Clock` (UTC, `KernelClockConfig`, not a stub) is the one clock, as 19A section 13 says; `BusinessDate.current` takes the location id, not the scope, because a business date belongs to a location and an entity-wide scope has none. `CalendarBusinessDate` reads that clock and takes its zone from `coop-erp.business-timezone`, as `SeedConfigRegistry` now does: the zone was written in three places. New architecture rule with a bite fixture: a business module never reads the wall clock (`Instant.now()`, `LocalDate.now()`, `System.currentTimeMillis()`, `new Date()`). New `DevStubsGuard`: a warning at every start that identity and scope come from unauthenticated headers, and a refusal to start under a `prod` or `production` profile. Left for 19A, on purpose: `ConfigRegistry` has no decimal or duration getter (K-11); the hello module shows no use of `Clock`, `BusinessDate`, `ConfigRegistry` or the document base, because a greeting needs none. The first pipeline run of this branch failed, usefully: `JsonMessages` had gained a second, test-only constructor, and with two constructors and no `@Autowired` Spring looks for a no-argument one, so the application did not start and all 21 integration tests failed. The unit tests had called the constructor by hand and could not see it. Fixed, and `KernelWiringTest` now builds the database-free kernel beans through Spring from their real constructors and property names (shown to fail without the fix), so the next mistake of this kind fails in `make test`, without Docker. Verified on the build machine: 81 unit tests (15 architecture rules, 17 bite tests), 43 tool tests, `make test`, `make check-generated`. **Not verified on the build machine:** the integration tests, `make test-scaffold` and the stack smoke, because Docker Desktop would not start there on 20 Sep (next entry); the pipeline runs all three on Linux, and the pull request is not to be merged before they are green.
