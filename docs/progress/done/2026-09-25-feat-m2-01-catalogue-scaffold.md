- **M2-01 catalogue scaffold, schema and seeds (25 Sep, branch `feat/m2-01-catalogue-scaffold`).** The first M2 ticket (22A section 10: "Migrations and seeds apply"). `make new-module NAME=m2catalogue SCHEMA=catalogue ENTITY=sku` was run, and its greeting-shaped copy (entity, handler, queries, controller, migration, dev seed, integration test, web page, message ids) removed again: hello keeps the tests that prove the template, and nothing of the copy was needed. The schema ownership was already in place (`m2catalogue` owns `catalogue` in `new-module.mjs`, which `check-schema-ownership.mjs`, `ArchitectureTests` and `FlywayConfig` agree with). **Schema** (`m2catalogue/V0001`, a new lane): `uom`, `tax_category`, `tax_rate`, `sku`, `sku_uom_conversion`, `sku_barcode`, `tag`, `sku_tag` and `batch` as 22A section 3 writes them, with the exclusion constraints on conversions and rates, the trigram indexes, B-I1 and B-I2; `batch` partitioned by month of `created_at` with `catalogue.ensure_batch_partitions(n)` (partitions get RLS forced and the parent's policies copied; V0001 creates this month and three more). Every table carries the RLS template (own_read/own_write on class OWN, fed_view, ext_view) plus `own_update` where it is updated, and the reference reads 22A asks for: `authenticated_read` (units, tax), `shared_read` (a SHARED SKU and its conversions, barcodes and tags; every batch), `governed_read` (governed tags); `seed_reference TO app_seed` on the seeded tables. Batch: INSERT and UPDATE(status) only. **Seeds**: `M2SeedLoader` (as the migrator, like `M1SeedLoader`) loads `uom.yaml` (10 units), `tags.yaml` (8 governed tags) and `tax.yaml` (STD 18 %, ZERO, EXEMPT, owned by the Federation from `coop-erp.system.entity-id`; skipped with a warning when it is not set), insert-if-absent; `audit-event-types.yaml` carries the 19 audit codes of 22A section 6. **Permissions**: M1's loader reads one file and `security.permission` is M1's, so the eleven `cat.*` codes are appended to `seed/m1party/permissions.yaml` as 22A section 3.1 says. **Slice** `m2catalogue.yaml`: info only, no operation (M2-02 adds the first). **Web**: the registration the scaffolder makes, with no route and no navigation entry. **Decisions**: the tables of later tickets (supplier, sku_image, sku_alias, duplicate_suspect, location_assortment) come with those tickets; collations and `gin_trgm_ops` qualified `kernel.`; the batch key is a unique index (22A's constraint holds an expression; it includes `created_at`, so RegisterBatch must look up first); `shared_read` tests the class `<> 'NONE'`; the kernel's `PartitionJob` takes no list of tables, so nothing calls the batch partition function daily yet, and M2-05 must settle it (a module job, or a registration hook in the kernel). **Not here**: any command, query or operation; the transliteration table (M2-08). **Proof**: `CatalogueSchemaIntegrationTest` (the nine tables, forced RLS and the exact policy set on every table and partition, own_* test the class, grants, partitions), `CatalogueRlsIntegrationTest` (12 rows of the matrix: OWN, SHARED, FEDERATION_VIEW, EXTERNAL, NONE, barcodes of shared items, batch read by all and changed by its registrant, printed MRP never edited, no unit written by the application), `M2SeedLoaderTest` (counts, translations, Federation ownership, a second run inserts nothing and leaves edits and later rates alone), `M1SeedLoaderTest` (28 permissions). `m2catalogue/README.md` is the living guide and lists what M2-02 to M2-09 build on.
