- **M2 catalogue decisions (27 Sep, branch `feat/decisions-m2-catalogue`).** Five open M2 items decided on the architect's delegation, the reasons on the change requests and in the module README (Deviations 11, 15, 23, 24, 27, 28). **The tag key** (CR-22A-1, accepted as revised; 22A sections 3 and 6, doc 22 section 3.5, 18 Part F): `m2catalogue/V0007` gives `catalogue.tag` a `tag_id` primary key and the unique index `tag_code_per_owner` on (code, owner or none), so two entities keep the same local code and a governed code may be introduced beside a local one, and no duplicate key reveals a hidden tag; `sku_tag` names the tag by `tag_id` (rows carried over by their code; key `(sku_id, tag_id)`) and its `own_write` admits only a governed tag or the caller's own; `governed_write` and `governed_update` let the Federation (`kernel.system_entity()`) write governed tags. No reserved prefix: the governed codes stay as the documents name them, and M2-03's DefineTag refuses a local code a governed tag has. `M2SeedLoader` and `CatalogueSnapshotContributor` follow the key. **Batch correction before M5** (22A section 6: "caller owns a lot of the batch or F"): `internal/integration/RegistrationLotQuery` replaces `NoInventoryLotQuery` and answers from M2's own batches (the registering entity of a batch, or of one it replaces, holds a lot; a SKU with a batch has lots), so a society corrects its own local-supply batch; M5's implementation replaces the class. **Suppliers** (22A section 3 gives the template only): V0007 replaces V0004's `authenticated_read` with `cited_read`, a supplier read beyond its owner only once a batch cites it (index `batch_key_supplier`); the RLS matrix exception for `supplier` is gone. **Thumbnails and image events** (CR-22A-2, accepted as revised; doc 22 sections 3.4 and 7): `Thumbnailer` writes a JPEG (`thumb.jpg`) within the new configuration item `m2.image.thumbnail_max_kb` (10, doc 22's `max_thumb_kb`), stepping the quality down to fit, transparent uploads laid on white; the split `image.pending.v1` / `image.attached.v1` / `image.failed.v1` and the audit codes `IMAGE_ACTIVATED`, `IMAGE_FAILED`, `IMAGE_RETIRED` confirmed. **Permission codes** (CR-22A-3, accepted; 22A section 3.1): `cat.sku.view` kept as the read code of the slice, `cat.tag.govern` (FEDERATION) added, `cat.tag.manage` now local tags only; the Federation Catalogue Steward template holds both tag codes; M2-03's DefineTag is to be one operation with `x-permission-any-of` routed to two handlers. **Tests**: `CatalogueRlsIntegrationTest` (the same local code in two entities, a governed code beside a local one, uniqueness within an owner and among governed tags, governed tags by the Federation only, another entity's local tag refused on an item, a supplier read by others only once a batch cites it), `BatchCorrectionBeforeM5PostgresIntegrationTest` (the registering entity corrects, another entity is refused with nothing committed, the registrant corrects after the Federation's correction, a SKU has lots once a batch exists), `ThumbnailerTest` (JPEG, the 10 KB budget for a photograph, the smallest kept, transparency on white), `ImageHandlersPostgresIntegrationTest` (`thumb.jpg`), `CatalogueSchemaIntegrationTest`, `CatalogueSnapshotContributorIntegrationTest`, `CatalogueHttpPostgresIntegrationTest` (the refused correction is now by an entity that did not register the batch), `RlsMatrixIntegrationTest`, `M1SeedLoaderTest` (38 codes with the M1 decisions of #143). `make reset` not needed.
