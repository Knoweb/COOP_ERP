- **Sync gateway, configuration register and cache fan-out, the review fixes (26 Sep, branch `fix/sync-config-caches-review`).** The findings of the review of 25 September on K-08, K-11 and the K-02 follow-up. **Gzip bounded and behind the token** (`GzipRequestFilter`): the compressed read stops one byte past `sync.batch.max_bytes` (doc 32 DR-1, the register's value for the device's scope, the federation's for the enrolment call) and answers 413 `sync.batch_too_large`; the filter runs after the security chain and on `/v1/sync/` paths alone, so an anonymous body is never inflated and a compressed body elsewhere is left as sent; `IdempotencyFilter` moved behind the security chain with it (its body read was the same exposure), so the idempotency hash covers the inflated body. **A replayable enrolment** (`EnrolmentStore.enrol`, `kernel/V0081`, lane D): the code row keeps the Idempotency-Key it was spent with; a retry with that key, the same serial and the code still within its lifetime is enrolled again (doc 32 section 8: the till holds no credential until the answer arrives) with a credential of its own, since the first was never delivered and a secret is never stored; any other key learns nothing, and a new code ends the window. **The heartbeat holds no lock** (`HeartbeatService.record`): the cursor is read plain and the resend request written conditionally on the sequence it was decided on, so a heartbeat overlapping the next batch's `FOR UPDATE NOWAIT` claim no longer makes a false 409 `sync.batch_in_flight`. **The enrolment code is gated on `sys.device.enrol`** (M1's device permission; `sys.device.manage` stays unused for the freeze) through the kernel's one permission rule, **`PermissionGate`** (security package), which `CommandInterceptor` and `EnrolmentStore` both call: roles, then the register's freshness window, refused only under enforcement. **`complete()` of a taken-over claim is the in-flight conflict** (`IngestTransactions`): zero rows from the release is `ClaimLost`, 409 naming the holder, not a result-size 500. **A shop with nothing published is an empty page** (`ChangeLogReader`): since 0 with a current version of 0 is not a full snapshot, so a till enrolled before any publication starts. **The idempotency hash is keyed** (`IdempotencyFilter`): HMAC-SHA256 under `coop-erp.idempotency.hash-secret`, so a stored hash of a body carrying a PIN gives the PIN back to nobody; no default outside a development issuer, and a changed secret makes a key first used before it answer `request_mismatch` for the retention window (24 hours). **Caches empty on every instance** (`CacheFanoutListener`, `RabbitCacheFanoutRuntime`, event package): each instance, in every role, holds an exclusive auto-deleted queue on the domain exchange bound to the types its caches name, and hands a delivery to the permission, configuration and device caches directly, past the shared consumer queues and the inbox, which deliver once to one instance; the worker's consumers stay as before; the broker's address moves to `application.yml` for every role, the health indicator stays worker-only, an instance without a broker serves its caches to their expiry and tries again every minute; the test contexts turn it off. `JdbcConfigRegistry.set()` already emptied its cache after commit (#116). **An unregistered key fails the start** (`ConfigItemSeedLoader.registerModuleDefaults`): a module default for a key not in `seed/kernel/config-items.yaml` used to become an untyped ENTITY-scoped string item that `set()` accepted any text for without a second factor; `m1.relationship.credit_limit_mfa_max_age` is now a typed, bounded, sensitive item. **The PIN policy can only be tightened**: `security.pin.lockout_attempts` at most 5, `security.pin.lockout_duration` at least PT15M, `security.pin.history_depth` at least 3 (doc 19 section 2.1). **Deviations**: the enrolment retry and the compressed-read limit, below. **Proof**: `PermissionGateTest`, `IdempotencyFilterTest`, `RabbitCacheFanoutRuntimeTest` (the queue's shape, the union of types, a delivery to every cache of its type and no other, the same event twice, a failing cache and an unreadable message), `EnrolmentIntegrationTest` (a retry with the same key answered again, another key or serial refused, a new code ends the window), `HeartbeatConformanceIntegrationTest` (a heartbeat while a batch holds the cursor), `CrashAndConcurrencyConformanceIntegrationTest` (`complete()` after a takeover), `ChangeLogIntegrationTest` (an empty shop), `BatchUploadConformanceIntegrationTest` (a compressed body over the limit, one without a token), `ConfigRegistryPostgresIntegrationTest` (an unknown key refused, the PIN bounds), the sync, config, idempotency, hello and revoke suites, and the unit suite.
