- **K-07 documents and numbering base (24 Sep, branch `feat/k-07-documents-and-numbering`).** The document base of doc 18 part C as the kernel schema and the services 19A section 7 names, taken up because M1-05 (locations and till positions: "NumberingService hooks") waits on it and nobody had it. **Schema** (`kernel/V0050`, lane C): `document_type` (reference data, seeded and upserted from `seed/kernel/document-types.yaml`, the seventeen kinds with the 24B flags, names in three languages), `numbering_series` (one counter per series, `UNIQUE NULLS NOT DISTINCT` on type and scope, `fy_reset` pinned false by a check as 24B N-1 decided), `document`, `document_line`, `document_link`, `document_state_history`, `document_attachment`. C-I1 by the trigger of 19A (`document.immutable` as a check violation) plus insert-only triggers on the rows and grants to match; C-I2 by `UNIQUE (series_id, doc_number)` and `kernel.numbering_gaps()`. **Policies:** the template on `numbering_series` and `document` (with `party_read`, and an `own_update` for the counter and for what issuance fills on a stored draft); the rows of a document carry no owner column and get `document_read`/`document_write` on two `SECURITY INVOKER` functions that ask the header under the caller's own policies (a fourth case, added to `RLS_POLICY_TEMPLATE.md`). **Services** (`kernel.api`): `NumberingService` (`registerSeries` idempotent, `holderChange`, `closeSeries`, `activeSeriesOf`; prefix `{entity_code}[-{location_code}[-T{position}]]-{type}`, display `{prefix}-{number:07d}`; audited and published as `series.*.v1`), `DocumentIssuance` (the protocol of doc 18 section 5.5 in the order of 19A: base checks, the type's validator, the number by `UPDATE ... RETURNING`, totals, `content_hash` over a canonical text form a till can reproduce without a JSON library, the rows, the DRAFT to ISSUED history row, `DOCUMENT_ISSUED`, the post-issue hook, `document.issued.v1`), `DocumentTypeHandler` (what a module registers per type it owns: validate, afterIssue, isReversible; a type nobody owns cannot issue), `DocumentLinks` (REVERSES once and only while reversible; SETTLES and CREDITS within the open balance; SUPERSEDES drafts only), `DocumentTypes`. `JdbcDocumentBaseRepository` replaces the 17A in-memory stub. `GapCheck` reads the density function nightly as a federation-wide viewer and logs what it finds. **Two things said out loud for the architect.** (1) The document tables are **not partitioned**: 19A partitions the volume tables by month on `received_at`, but a partitioned header cannot be the target of the plain foreign key on `document_id` that doc 18 gives every module extension table (I-F10) and every link; `received_at` is on every table so that partitioning can be added by a rebuilding migration when the volume asks. (2) The `NUMBERING_GAP` REVIEW audit record and the "unless explained by sync_quarantine" exception wait for K-12 (a scoped system job: an audit record needs an OWN scope, which a nightly job has not) and K-08 (the quarantine table). **Proof** (`DocumentBasePostgresIntegrationTest`, as the application user): registering twice gives one series; a series is registered by its owner only; holder change audited and published; issuance numbers, freezes totals, hashes, stores lines and history, audits and publishes, runs the hook; the hash recomputed from the stored rows equals the stored one; an invalid draft takes no number; a failure after the number leaves neither and the next issuance takes the same number; twenty concurrent issuances from four threads are dense 1 to 20; bilateral without counterparty, unknown and unowned types refused; a closed series issues nothing; an issued header changes only its status (repository, trigger for the superuser, no UPDATE privilege on lines); REVERSES twice and SETTLES beyond the balance refused; SUPERSEDES drafts only; the gap check flags a fabricated gap and nothing on a dense series; the counterparty reads the document and its rows, a stranger nothing, and cannot write a line to it.
