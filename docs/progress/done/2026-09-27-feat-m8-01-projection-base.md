- **M8-01: the projection base, with the stock position as its sample projection (27 Sep, branch `feat/m8-01-projection-base`; demo lane, phase 4).** 28A sections 3, 4, 6 and 9; doc 28 sections 3 and 4. **Pattern** (`m8reporting/internal/projection`): `Projection`, the base of every read model: a consumer of every event type (`"*"`, because only that consumer is handed the envelope with the event's id and time, EventConsumerDispatcher) that ignores the types it does not read, applies the event in the OWN scope of its owner under row-level security, and advances `projection_state` (per projection and entity: the last event applied; the latest wins). Every apply is idempotent by construction (facts `ON CONFLICT DO NOTHING`, figures overwritten with the value the event reports and guarded by the event's order), so a replay or a redelivery changes nothing. Payloads are read as JSON by field name; M8 imports no module's api. **Stock position** (`reporting.stock_position`, M8-03 part): one row per (location, batch, condition) from `stock.moved.v1`, taking the lot's quantity after the movement (`lotQtyOnHand`) and the entity average at the movement as unit cost (CR-28A-1); the movement number (dense per location and source) keeps an older movement from overwriting a newer one. **Schema** `m8reporting/V0001__projection_base.sql`: both tables with the template's policies (no PARTY policy on the stock position, which carries cost); `app_rw` has SELECT, INSERT and UPDATE of the figures, no DELETE. **Decision** (27 Sep, on the architect's delegation): `ArchitectureTests.onlyHandlersWriteRule` exempts the package `m8reporting.internal.projection` and nothing else, because a projection row copies facts already audited and published by their owner and auditing each copy would double the audit log (README). **Rebuild**: an operator's procedure until the rebuild service exists (empty the tables as the migration user, clear the consumer's inbox rows, `Replayer.replay("m8.<name>", 0)`), which is what the equivalence harness does. **Proof** (`StockPositionProjectionPostgresIntegrationTest` with the reusable `ProjectionHarness`): rebuild equivalence over five random streams of 60 movements with redeliveries (two entities, six locations, two sources); a late and a repeated movement change nothing; another type is ignored; a delivery in another entity's scope is refused by row-level security; nothing audited or published. `RlsMatrixIntegrationTest` and `SchemaRulesIntegrationTest` cover both tables.
