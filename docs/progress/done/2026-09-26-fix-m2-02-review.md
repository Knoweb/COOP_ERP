- **M2-02 review fixes (26 Sep, branch `fix/m2-02-review`).** The findings of the review of pull request #115, in `m2catalogue`. **The shared path is the Federation's** (`FederationCaller`): creating a shared SKU, activating one and editing one require the caller's entity to be the Federation, the entity `coop-erp.system.entity-id` names (M2 may not read M1's entity table; M2SeedLoader and the kernel's federation-wide configuration use the same setting), refused with `m2.sku.federation_only`; the permission alone was not enough while enforcement is off. **The router follows the SKU** (`SkuCommandRouter`): an update goes to the shared path when the SKU is SHARED and to the local path otherwise, never by the caller's permissions, and the local handler refuses a SHARED SKU; create always makes a DRAFT, so the byte-identical `CreateSharedSkuHandler` is gone and create is `cat.sku.create_local` alone. **Code clashes**: under row-level security the handler cannot see other entities' codes, so a clash surfaced as a 500; the router now runs the create again with a fresh code when the insert meets the unique index on `sku_code` (at most five times, then `m2.sku.code_generation_failed`). **Search** (22A section 7): the name columns bare so their trigram indexes apply, the code by prefix (`m2catalogue/V0002` adds a `varchar_pattern_ops` index for it), `%`, `_` and `\` in the text escaped, the closest match first after the collation order; the offset is capped at 10,000 (also `maximum` in the slice). **Shared activation** audits `SKU_SHARED` and publishes `sku.shared.v1` (`SkuShared`); the local path keeps `SKU_ACTIVATED` and `sku.activated.v1`. **Reads** check `cat.sku.view` in the controller for the OWN class when permissions are enforced (no command interceptor runs for a read); a missing SKU is the problem `m2.sku.not_found`, now 404 in `ProblemResponses`, and the slice says so; the create's "not visible after create" is that problem too instead of an `IllegalStateException`. **The lots guard** has its own message, `m2.sku.has_lots`. **Role templates**: the Entity Administrator gains `cat.sku.create_local` and `cat.sku.deactivate`; a new OWN template, Federation Catalogue Steward, holds `cat.sku.view`, `create_local`, `create`, `promote` and `deactivate` (four templates now). **Deviations**: the offset cap is a constant, not a configuration item, until the list moves to the cursor of 22A section 4; duplicate scoring stays deferred as above. `make reset` is not needed (V0002 is a plain new migration). **Proof**: `SkuHandlersPostgresIntegrationTest` (a society refused the shared path; the router by status; the Federation refused another entity's LOCAL SKU; a forced code clash retried, and one that keeps clashing ending in the problem; the lots guard with a stub `InventoryLotQuery`; `SKU_SHARED` and `SkuShared`), `CatalogueQueriesPostgresIntegrationTest` (`%`, `_`, `\` are letters; the code by prefix only; similarity after the collation; the offset cap), `CatalogueHttpPostgresIntegrationTest` (a replayed create answers the first SKU and creates nothing; the 404 problem), `CatalogueControllerViewPermissionTest`, `M1SeedLoaderTest`.
