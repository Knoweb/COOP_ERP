- **K-06b: the A4 renderer (27 Sep, branch `feat/k-06b-a4-renderer`; PLAN_TO_M2 task 6.13, decided in PR #145, CR-19A-8 item 7; demo lane).** 19A section 6 ("A4Renderer: HTML templates (Thymeleaf) rendered to PDF by a headless Chromium worker with bundled Noto fonts ... Output to object storage; report.rendered.v1") and its Tests row (the golden trilingual PDF compared by text extraction); doc 19 section 5 and DR-3. **`kernel.api.A4Renderer`**: `render(templateId, data, language, ctx)` fills `reports/templates/{templateId}.html` with Thymeleaf (the core library, no starter; `#{id}` reads the kernel's catalogue in the requested language), puts the charset, a content security policy (`default-src 'none'`, fonts and images as data URIs only) and the three Noto families of the web client (Noto Sans, Noto Sans Sinhala, Noto Sans Tamil; the fontsource 5.3.0 woff2 files, regular and bold, SIL OFL, `reports/fonts/`) into the page's head, prints it with Chromium, stores the PDF through the kernel's `ObjectStore` under `reports/{entity}/{reportId}.pdf` (the store of PR #139, now public inside the kernel), and in one transaction of its own audits `REPORT_RENDERED` (seeded) and publishes `ReportRendered` (`report.rendered.v1`: id, template, language, key, size, hash, entity; never the data); it answers the key and a pre-signed GET. `presignGet(objectKey, ctx)` renews the link for the entity's own scope. Guards: an OWN scope (`report.scope_mismatch`), a template id `[a-z0-9-]+` (`report.template_invalid`) that exists (`report.template_unknown`), and on an instance without the worker role `report.renderer_unavailable`. **Limits** are register items: `report.render.timeout_seconds` (60; the browser is killed), `report.render.max_bytes` (10 MB of PDF), `report.render.max_html_bytes` (5 MB of page). **Rendering runs on the worker only**: `coop-erp.report.enabled` is true in `application-worker.yml` alone, so a module prints from what the worker runs, a K-12 job (M3's label job) or an event consumer (an M4 document issued on the web role, printed by a consumer of its event), and the web role hands out `presignGet` links. **The worker image**: `infra/worker-image/Dockerfile` (Debian 13 slim, its `chromium` package, and the JRE copied from `eclipse-temurin:21-jre`), built by `make image` as `coop-erp/worker-base:dev`, and Jib puts the application on it with `-PjibWorker=true` as `coop-erp/backend-worker:dev`; `coop-erp/backend:dev` (web, ingest) keeps the plain JRE. The compose backend runs web and worker in one container, so it now starts the worker image; the weekly security scan scans both images. **For M4**: the generic template `document-a4` (title, number, date, references, issuer, from, to, lines, totals, notes, footer; the model in `reports/templates/README.md`) is the demo's printable invoice; M4 fills it with values formatted by `Formats` and calls `render` from a worker-side consumer. m4trading is not touched. **Proof**: `A4RendererPostgresIntegrationTest` (tagged `integration` and `chromium`) prints a trilingual invoice in Sinhala with a real Chromium and checks the PDF with PDFBox 3.0.5 (test scope): A4, the text extracts to the Sinhala, Tamil and English strings that went in (with a catalogue label in Sinhala), every font embedded and the three Noto families among them; stored with its hash, audited and published once, the link refused to another entity; the guards refuse before anything is printed; the data is escaped and the page carries the policy; a PDF over the limit, a browser past the timeout and a missing binary are refused. Locally on Chrome 154 (the rendering took 1.3 s, 41 KB; `--virtual-time-budget` was dropped after it hung on the pipeline's Linux Chrome); the pipeline runs it with the worker image's own Chromium (`tools/chromium-in-docker.sh`, `CHROMIUM_PATH`; the runner's Google Chrome never exited after printing, and the integration job builds the worker base first, about two minutes), and the test fails rather than skips there (`CI` set) when none is found. The worker image was built locally (1.6 GB against 0.6 GB for the plain image; the Chromium layer took under two minutes to build) and its Chromium printed a page as user 10001. `make reset` is not needed (no migration).
