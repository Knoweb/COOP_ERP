- **The demo till sale runs against a live stack (28 Sep, branch `fix/dev-password-grant-mfa`).** The first live run of `make demo-till-sale` found two faults. **The password grant carries no `auth_time`**, so on the development realm a fresh password sign-in did not count as the step-up and device enrolment answered `mfa.required`: `JwtClaimsMapper.mfaAt` now takes the token's `iat` when `password-reauth-counts` is on and `auth_time` is absent (development issuers only; elsewhere a token without `auth_time` still has no second factor). **The demo's before and after stock read 0**: it looked each SKU up by searching the catalogue for its barcode, which the search does not match; it now finds the SKU by its English name. Proof: `JwtClaimsMapperTest` (an `iat`-only token counts on the development realm and not elsewhere), and a live run: the till enrolled, sold three items and the shop's stock went 5→4, 6→4, 1→-2. Found on the way and handed to its own fix: central does not track a till's receipt numbers, so a re-enrolled till reuses them unflagged.
