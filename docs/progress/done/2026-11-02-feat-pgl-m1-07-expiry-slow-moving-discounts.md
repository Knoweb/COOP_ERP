- **Expiry / Slow-Moving Discounts (Polgolla Member 1 ticket PGL-M1-07, branch `feat/PGL-M1-07-expiry-slow-moving-discounts`):** Implemented automated markdown and discount evaluation for near-expiry and slow-moving inventory stock in `m3pricing` without querying M5 private tables directly, consuming authoritative candidates via question interface `InventoryCandidateQuery` in `m3pricing.api` implemented by `@Component` `InventoryCandidatesForPricing` in `m5inventory.internal.availability` delegating to published `InventoryQueries#nearExpiryLots` and `InventoryQueries#slowMovingStock`; applied configurable markdown rules with configuration items in `config-items.yaml` (`pricing.expiry_discounts_enabled`, `pricing.near_expiry_discount_critical_percent`, `pricing.near_expiry_discount_warning_percent`, `pricing.slow_moving_discount_stagnant_percent`, `pricing.slow_moving_discount_slow_velocity_percent`, `pricing.max_markdown_percent`); enforced non-stacking conflict resolution where strongest eligible markdown wins, imminent expiry (`CRITICAL`) takes precedence over slow-moving, discounts are capped at safety ceiling (`max_markdown_percent`), zero/negative stock lots are skipped, and expired goods (`EXPIRED`, daysToExpiry < 0) are strictly excluded from both near-expiry and slow-moving discounting; base price resolves dynamically through `RetailPriceResolution` falling back to acquisition unit cost; exposed public read seam `PricingQueries#listExpirySlowMovingDiscounts` and orchestration command `EvaluateExpirySlowMovingDiscounts` handled by `@Service` `@CommandHandler(permission = "prc.rule.activate")` `EvaluateExpirySlowMovingDiscountsHandler` with audit trail (`EXPIRY_SLOW_MOVING_DISCOUNTS_EVALUATED`), and domain event publication (`pricing.expiry_slow_moving_discounts_evaluated.v1`); added OpenAPI endpoints `GET /v1/pricing/expiry-slow-moving-discounts` and `POST /v1/pricing/expiry-slow-moving-discounts/evaluate` to `openapi/m3pricing.yaml`; added trilingual translations for all audit codes, error messages, and UI labels in `i18n/m3pricing/{en,si,ta}.json` and `pricing.messages.json`; upgraded web UI `MarkdownQueuePage.tsx` with shop selector, summary metric cards, filter controls (reason, status, search), data table with status badges and formatted currency, and manual "Evaluate Markdowns" action with real-time feedback; verified via unit tests (`ExpirySlowMovingDiscountCalculatorTest`, `EvaluateExpirySlowMovingDiscountsHandlerTest`), real PostgreSQL integration test (`ExpirySlowMovingDiscountsPostgresIntegrationTest`), web unit and design compliance tests (`MarkdownQueuePage.test.tsx`, `moduleStyle.test.ts`), and repository sanity tools (`check-permissions`, `check-slices`, `check-i18n`, `check-frozen-contracts`, `check-schema-ownership`, `spotlessApply`).
