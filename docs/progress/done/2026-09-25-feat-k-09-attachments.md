- **K-09 attachments (25 Sep, branch `feat/k-09-attachments`, on top of K-11).** The presign and the verifier of 19A section 9 on the `document_attachment` table K-07 created. **API** (`kernel.api.Attachments`): `presignUpload(documentId, attachmentId, contentType, sha256Hex, ctx)` records the attachment PENDING under the document's policies (a document the caller cannot see is "not found", one it can see but does not own is refused by the row policy) and returns a pre-signed PUT of fifteen minutes for the key `attachments/{entity}/{documentId}/{attachmentId}`, audited `ATTACHMENT_PRESIGNED`; `presignDownload` gives a pre-signed GET only for a COMPLETE attachment of a document the caller can read (the document's RLS is the scope check); `status`. **Store**: an `ObjectStore` boundary (presign PUT, presign GET, HEAD, SHA-256) with `S3ObjectStore` behind it on the AWS SDK v2 S3 client, path-style, provider-neutral; two endpoints, the one the backend reaches and the public one a browser or a till reaches with the URL (compose: `minio:9000` and `localhost:9000`), settings under `coop-erp.object-store`. **Verifier** (`attachment-verify`, a K-12 job every five minutes): reads PENDING rows as a federation-wide viewer and, in the OWN scope of each document's entity, COMPLETEs an object whose hash matches what the client announced (or takes the store's hash when nothing was announced) with `ATTACHMENT_COMPLETED` and `attachment.completed.v1`, FAILs a mismatch or an object not uploaded inside the upload window (24 h) with an `ATTACHMENT_FAILED` REVIEW record. **Proof**: `AttachmentsPostgresIntegrationTest` with an in-memory store (presign records PENDING on the caller's own document; a stranger cannot attach and the counterparty cannot either; the verifier completes an uploaded object with the right hash and the owner and the counterparty then get a URL, a stranger none; a wrong hash and an object that never came are FAILED; a malformed hash is refused) and `S3ObjectStoreIntegrationTest` against a MinIO container (a pre-signed PUT uploads; HEAD, hash and a pre-signed GET agree; a missing key is absent). **Not here:** the sync endpoint `POST /sync/v1/attachments/presign` (K-08) and the image thumbnails (M2-11).
