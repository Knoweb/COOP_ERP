- **Identity and permissions, the review fixes (25 Sep, branch `fix/identity-review`).** The code review of the twenty-one pull requests of 24 and 25 September found four access-control defects in K-02 and K-03b and eight lesser ones; this fixes them together, in the kernel's security package. **Scopes are the assignments and nothing else** (`JwtClaimsMapper`): the home entity is where a user belongs, not where they act, so a cashier assigned at one shop no longer reads the whole society entity-wide; a read-only class keeps its home entity as the nominal scope; the test provider carries a `scopes` claim as 19A's provider mapper would. **An entity-wide holder may act at any location of the entity** (`ScopeFilter.holds`, doc 19 section 3.1). **A login the platform creates carries `ent` and `cls`** (`KeycloakAdminClient.createUser`), so a new user's tokens have a class. **User management is entity-wide** in the provider client: a location-scoped caller is refused, so a shop manager cannot reset the entity's administrators. **`resetTotp` keeps the pending required actions.** **Tokens must be issued to a client of the platform** (`AcceptedClientsValidator`, `coop-erp.security.oidc.accepted-clients`, tills by prefix). **The second factor from standard claims**: `mfa_at`, else `auth_time` when `acr`/`amr` names a second factor, or on a development stack where a fresh password sign-in counts (`coop-erp.security.mfa.password-reauth-counts`, compose only). **One freshness rule** (`StepUp`, the register's `security.mfa.freshness`, twelve hours by default) for the interceptor, the register and the enrolment store. **The permission check runs before the idempotency branch**, for every caller that names a user. **Caches empty on the changing instance after commit** (`PublishedEventListener` from `OutboxWriter`), the grant events empty the grant cache, the expiry is a minute, and the configuration register's cache empties after commit rather than before. **A ROLE pair refuses the same person** (`JdbcSod`). **Not here**: the per-instance fan-out queue on every profile, enforcement on by default, the web shell's replay after step-up. **Proof**: `JwtClaimsMapperTest`, `StepUpTest`, `TokenAuthenticationPostgresIntegrationTest` (another client refused, an entity-wide holder at a location), `KeycloakAdminClientIntegrationTest` (ent/cls, a shop-scoped caller refused, UPDATE_PASSWORD kept), `PermissionResolverPostgresIntegrationTest` (a ROLE pair), and the hello, M1, M3, sync, config and role suites.
