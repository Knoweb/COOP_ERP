- **Spring Boot 3.5 (CR-17A-2) (21 Sep, branch `chore/spring-boot-3.5`).** The change request was accepted by the architect on 21 September and is applied here: Spring Boot 3.3.13 to 3.5.16, Spring Modulith 1.2.13 to 1.4.13 (the line that matches Boot 3.5), `io.spring.dependency-management` stays 1.1.7 (already current). Everything else moved with the Boot version, because the catalogue names none of it: Spring Framework 6.1.21 to 6.2.19, Tomcat 10.1.42 to 10.1.55, Hibernate 6.5.3 to 6.6.53, Jackson 2.17.3 to 2.21.4, the PostgreSQL driver 42.7.7 to 42.7.11, Flyway 10.10.0 to 11.7.2, Micrometer 1.13.15 to 1.15.12, JUnit 5.10.5 to 5.12.2, AssertJ 3.25.3 to 3.27.7. **The Testcontainers override is gone.** The catalogue pinned 1.21.4 because Boot 3.3 managed 1.19, which Docker Engine 29 refuses; Boot 3.5.16 manages exactly 1.21.4 itself, so the `testcontainers` entry and the `extra["testcontainers.version"]` line in `app/build.gradle.kts` were removed with their comments and the 28 integration tests still run against PostgreSQL 16 in Docker 29.8. **What broke: nothing that failed a test.** Two APIs became deprecated-for-removal and were replaced: `MethodValidationResult.getAllValidationResults()` is now `getParameterValidationResults()` (`RequestValidationHandler`), and `Documenter(ApplicationModules, String)` is now `Documenter(MODULES, Documenter.Options.defaults().withOutputFolder(...))` (`ArchitectureTests`). The `HandlerMethodValidationException` fallback that 17A's S0-06 work wrote against Spring 6.1 — constraint name from `getCodes()`, attributes from `getArguments()` in alphabetical order — was left as it is: Spring 6.2 changed method validation internally but not that shape, and `RequestValidationHandlerTest` proves it by all three routes, so there was no reason to rewrite working code. No configuration property we use was renamed or removed by Boot 3.4 or 3.5 (checked against the configuration metadata of 3.5.16: `management.endpoint.health.probes.enabled`, the actuator exposure list, `server.shutdown`, `spring.lifecycle.timeout-per-shutdown-phase`, `spring.jpa.properties.*` are all current), and `FlywayConfig` needed no change across Flyway 10 to 11 because `flyway-database-postgresql` was already a dependency. **Generated module docs changed and are committed:** Modulith 1.4 writes `format=svg` into every `plantuml::` line of `docs/modules/all-docs.adoc` and orders the modules differently (Config first), and `module-kernel.adoc` gained an "Events listened to" row for `ApplicationReadyEvent`. **The vulnerability scan, the point of the exercise** (same procedure as `security-scan.yml`: `:app:cyclonedxBom`, Trivy 0.67.2 `--ignore-unfixed --severity CRITICAL,HIGH`, `tools/vulnerability-report.mjs`): **6 CRITICAL and 25 HIGH before, 3 CRITICAL and 1 HIGH after**, on the backend bill of materials. (The 7 and 31 the change request quotes were measured on Spring Boot 3.3.5 on 20 September; the branch starts from 3.3.13, which #43 had already merged, so 6 and 25 is the honest baseline.) Gone: Spring Framework, `spring-boot`, `spring-boot-starter-actuator`, `spring-data-commons`, Jackson, Micrometer and AssertJ. **What remains, for the architect:** `tomcat-embed-core` 10.1.55 needs 10.1.58 (3 CRITICAL: CVE-2026-65182, CVE-2026-65905, CVE-2026-68525) and `org.postgresql:postgresql` 42.7.11 needs 42.7.12 (1 HIGH: CVE-2026-54291). Both are versions Spring Boot manages and both would be cured by one line each in `app/build.gradle.kts` (`extra["tomcat.version"] = "10.1.58"`, `extra["postgresql.version"] = "42.7.12"`); no override was added, because overriding a managed version is the thing the catalogue's own comment warns about and the next Boot patch release should carry both. `.github/dependabot.yml` keeps Spring Boot and Modulith on their minor line as before — the hold is by update type, so it works unchanged on 3.5 and 1.4; only the comments that named 3.3.x and 1.2.x were rewritten. ADR-052 gained a dated note that the untested "Gradle 9 with the Boot 3.3 plugin" combination it describes has ended. 17A section 3 still says 3.3.x / 1.2.x and is not re-issued yet; `AGENTS.md` and `README.md` say 3.5 / 1.4 with that caveat.
