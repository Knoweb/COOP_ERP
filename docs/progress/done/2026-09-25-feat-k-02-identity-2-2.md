- **K-02 identity, second pull request (25 Sep, branch `feat/k-02-identity-2`, on top of the first).** The development headers are gone on both sides: every request under `/v1` needs a token (401 `auth.required` without one, `token.invalid` for one the resource server refuses); `DevScopeContextProvider` and `DevStubsGuard` are deleted, the web client sends the bearer token and `X-Scope-Entity` (the caller's choice of active scope, which stays), the smoke test signs in with the password grant. **Scopes from the platform's records**: 19A section 2 puts `scopes` and `roles` into the token through a provider mapper calling a kernel endpoint; our provider has no such mapper without a provider-specific extension, so `JdbcUserScopes` resolves the same facts at request time from M1's `user_role` (and `external_grant` for an EXTERNAL_TIMEBOXED caller) as the federation-wide viewer, cached ten minutes and emptied by the same events as the permission cache; a token that carries `scopes` or `grants` is honoured as it is; the scopes are the home entity (entity-wide) plus the assignments. **`IdentityProviderClient` implemented** as `KeycloakAdminClient` over the provider's plain administration REST API, no provider library: create a login (the platform's user id travels as the `uid` attribute and claim, read before `sub`), disable, one-time password, second-factor reset, end sessions; the scope rule of ADR-18 (the caller acts in the OWN class of the target's home entity, else `identity.scope`) runs before every call; the service account is a confidential client with `manage-users` and nothing else; every method takes the caller's `ScopeContext` (a departure from CR-19A-1's proposal, which had no caller). **Step-up in the web shell**: 401 `mfa.required` sends the user to the identity server with `prompt=login` and back to the same page. **The dev realm** declares the platform's user attributes in its user profile (Keycloak 24+ keeps only declared attributes written through the administration API) and carries the service account. **Not here**: device authentication (needs M1-06's devices), the provider mapper endpoint (replaced by the request-time resolution; the architect may want the claims in the token instead). **Proof**: `TokenAuthenticationPostgresIntegrationTest` (as before, plus: a token without a home entity acts where the assignments put the user; no token is 401 `auth.required`), `JwtClaimsMapperTest` (uid before sub, records plus home entity, an external caller's grants), `KeycloakAdminClientIntegrationTest` (against the provider of the local stack started with the same realm file: the scope rule, create, a taken name, one-time password, TOTP reset, sessions, disable, as the realm administrator then sees it). Every HTTP test of the repository now signs its requests through `TestIdentityProvider` in the shared test base, so the claims mapper and the scope filter run on every request of every module test.
