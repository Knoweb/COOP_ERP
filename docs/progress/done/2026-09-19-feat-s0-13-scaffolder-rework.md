- **S0-13 scaffolder (19 Sep, branch `feat/s0-13-scaffolder-rework`).** `tools/new_module.py` is replaced by `tools/new-module.mjs` (Node, standard library only; Python was an undeclared dependency and absent from the build machine). `make new-module NAME=m2catalogue SCHEMA=catalogue ENTITY=sku` copies the whole hello template: backend package with a module descriptor and a README written for the new module, migration, slice, seed file, the sixteen integration tests, web module; it registers the module in the three i18n catalogues, `web/src/router.tsx` and the web message catalogue (marker comments), then generates the web client. It validates the module against its schemas, refuses to overwrite, treats a folder holding only `.gitkeep` as empty (the old script refused every planned module but one), refuses an aggregate whose class name would clash with an import of the template (`Entity`, `List`) or with an existing aggregate, and has a dry run. The Makefile now finds the POSIX shell of Git for Windows by itself, so every target works from PowerShell and cmd as well as Git Bash (the first real use, from PowerShell, failed on `sed` and `sh`). Sixteen tool tests run in `make test` and CI against a temporary copy of the template, so they do not depend on which modules exist; one of them fails if the tool's module table drifts from `ArchitectureTests` or `FlywayConfig`. Done criterion proved and made repeatable as `make test-scaffold` (also a CI job): a scaffolded `m3pricing` compiled, kept every architecture rule green, passed its sixteen inherited integration tests against PostgreSQL and built in the web client. The two `m2catalogue` placeholders removed by pull request 17 are restored.
