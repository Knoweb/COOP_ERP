- **S0-07 web shell, step 5 of 5: the Playwright smoke test and the e2e stage (20 Sep, branch `feat/s0-07-playwright-e2e`).** Until this step nothing automated had ever signed in: every web test runs in jsdom with a session made up in the test, which is why the one defect that reached the architect's browser (a deep link lost at login, found and fixed in step 4) was invisible to the whole suite. `web/e2e` is eleven Playwright tests in a real Chromium against the running stack, typing the development password on Keycloak's own page — the one thing test code may do and a person or an agent may not. `make e2e` runs them the way `make smoke` runs the API checks: the stack must already be up (`make up` or `make up-2`; `TWO=1` is accepted and changes nothing, because nginx fronts both backends on the same port 8080 and neither the browser nor the tests can tell the difference, which is the point). **What they prove.** For each of the three development users: an anonymous visit to `/hello` lands on the identity server, and after signing in the browser is back on `/hello` — not on the start page — with the scope banner naming the user and the access class, the navigation entry and both headings in that user's language; Sinhala for mpcs-admin and Tamil for cashier although the browser asks for English, because the language comes from the token's `lang` claim. **The regression that is the reason for this step:** sign out, ask for `/_design`, sign in, and the design page must be shown. Shown to bite by creating the router at module load again, exactly as before the step-4 fix; it then fails with `expect(locator).toBeVisible() failed … getByRole('heading', { name: 'Design reference', level: 1 }) … element(s) not found`, and the reload test with the same message for the hello heading. Then: a reload keeps the user signed in without a form (tokens live in memory, the identity server's own session brings them back); the cashier sees the greetings and the read-only note and no form, mpcs-admin the form, the Federation view the greetings of both entities and the society only its own; a registered greeting appears in the list and the same text again shows the server's Sinhala refusal (`hello.greeting.duplicate`); signing out really ends the session and the back office is not reachable afterwards; an unknown address shows the translated "page not found" inside the frame. **Decisions where the brief left room:** the assertions read the real catalogues — `web/src/shell/i18n/messages.ts` for the client and `backend/app/src/main/resources/i18n/si.json` for the server's message — instead of Sinhala and Tamil typed into a spec, so a changed translation changes the test with it and a deleted message id fails loudly; every locator is a role or a text, never a class name; each run registers a text nobody has registered before, because the greeting table is insert-only and the stack is not reset between runs, so `make e2e` is repeatable against a stack it has already run against (it was run twice in a row to prove it); no retries, because a retry hides exactly the kind of fault this step exists to catch and every test starts in a fresh browser context; Chromium only (one browser keeps the pipeline short, and the back office is used on managed machines, not on whatever a visitor brings); two workers (more browsers do not make the stack answer faster and this build machine has little free memory); and the browser locale is fixed to English deliberately, so that Keycloak's own page always speaks one language while the back office speaks three. **Three changes the tests forced, each small and said so in the code:** `messages.ts` imports its JSON catalogue with the standard attribute `with { type: "json" }` (and so does the line `make new-module` writes into it, with the scaffolder test), because Node refuses a JSON import without it and the tests read that file directly rather than copying it; `web/tsconfig.e2e.json` is a second TypeScript project, so Node's globals are on for the tests and stay off for the browser code, where `process.env` would compile and then be undefined; `vite.config.ts` excludes `e2e/**` from Vitest and `playwright.config.ts` takes `*.spec.ts` only, so neither runner picks up the other's tests. ESLint covers `web/e2e` rather than ignoring it: it is the code the team will copy for a module's own end-to-end tests, and a typo there otherwise costs a pipeline run to find. **Pipeline:** the job `stack-smoke` already runs the two-instance stack, which is the "two instances: Playwright run alternates instances; nothing breaks" row of the 17A section 12 proof table, so the run goes there: Chromium installed with `--with-deps`, `make e2e` after `make smoke TWO=1`, and `web/playwright-report` with the traces uploaded when it fails. "Playwright run" is gone from the "not here yet" list at the top of `ci.yml`; the Android emulator smoke stays there, it needs S0-08. `make lint-ci` was run before the push, as the rule of the earlier silent-pipeline incident says. **Verified:** `make up`, `make smoke` (11 checks), `make e2e` (11 tests, 23.4 s) and `make e2e` again on the same stack (20.3 s); then `make down`, `make up-2`, `make smoke TWO=1` (11 checks including the alternation), `make e2e` (23.6 s); the regression run above against a deliberately broken router, and the file restored with `git checkout --` and green again (2 tests, 6.1 s); in `web/`: `pnpm lint`, `pnpm test` (103 web tests, unchanged: Vitest does not see the specs), `pnpm build`; 47 tool tests, `make test`, `make check-generated`, `make lint-ci`. Not verified on this machine: nothing in the tests; but Playwright's own browser download could not be used — Node's request to `cdn.playwright.dev` times out here while `curl` fetches the same file in seconds, so the four archives were downloaded with `curl` into `PLAYWRIGHT_BROWSERS_PATH=D:/tmp/ms-playwright` and unpacked by hand. A machine quirk, not a repository one; on the pipeline and on a normal machine `pnpm exec playwright install chromium` does it. **S0-07 meets its done criterion, "Login, banner, hello page in three languages": it is now a command anybody can run (`make up`, then `make e2e`), not a screenshot somebody once took.** Deferred, each with the ticket that lifts it: the scope switcher and entity names (M1 for the scope assignments, 19A K-02 for the `scopes` claim mapping); the step-up dialog (K-02, which issues the challenge); the temporary role-to-permission map in `shell/auth/permissions.ts` (K-03, the permission resolver — until then a hidden button is a courtesy and a direct request still succeeds); the nine other components of doc 30 (each with the module that first needs it); the headless component base library they will be built on (open item E-03).
