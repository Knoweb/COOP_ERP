- **For the architect, from the preparation branch.** The Flyway question is decided (architect, 21 Sep) and applied on the same branch: under the strict setting a lower-numbered migration merged after a higher one makes `migrate()` throw and, since it runs in a `@PostConstruct`, stops the application from starting, on developer machines only, because fresh databases never show it. So `coop-erp.migration.out-of-order` is now a configuration key, **false by default** (a deployed database must be reproducible from the files in order) and **true in the compose stack** (`MIGRATION_OUT_OF_ORDER`), where the lanes' ranges arrive in any order; `MigrationOrderDefaultTest` pins both halves, and doc 35 is to record that the question closes with the first deployed environment. **Decided 27 Sep 2026** (`CR-19A-1`, on the architect's delegation, docs group `docs/decisions-kernel-crs`): every one of these types has since been declared and built through K-02, K-03b, K-06, K-07, K-08 and K-10, reviewed at each merge; the re-issue of 19A takes its signatures from `kernel.api` as it stands rather than from a second, independently authored set.
