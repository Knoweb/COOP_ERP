- **The till: what it trusts, what it keeps (wave 2: TWK-01 to TWK-08, TWK-10, TWK-24's till half), decided on the architect's delegation (6 Oct, branch `docs/wave2-decisions`), CR-32-1 items 3 and 4:** (1) **Snapshot continuity** (TWK-01): the till refuses a delta whose `version` is below its current version, requires a non-full delta's signed `since` to equal its current version (else it asks for `since=0`), accepts any `since` on a full snapshot, compares the answer's `key_id` with the enrolled `signingKeyId`, and warns the supervisor when its last verified apply (`LAST_SNAPSHOT_AT`, the till's own clock) is older than `pos.snapshot_staleness_days` (doc 32 section 5.2, not implemented until now). Rejected: a previous-version hash in the manifest (deltas are built from each caller's `since`, so there is no one previous manifest to chain to); a signed issue time (an on-path attacker who can replay can withhold; the staleness warning is the control). No change to doc 32. (2) **https, trust on first use** (TWK-02, D-1): a server URL that is not `https://` is refused unless its host is `localhost`, `127.0.0.1`, `[::1]` or `*.localhost`, in `TillService.enrol` and when the identity is loaded at start (the trial databases re-enrol); the enrolment answer's `token_endpoint` must share the server's host unless the operator set `COOP_TILL_TOKEN_ENDPOINT`; `COOP_TILL_CA_FILE` names a trusted CA for a private certificate, never a trust-all switch; the signing key stays trusted on first use over TLS, bound to the one-time code the shop's manager issued minutes before. Rejected: a key fingerprint in the installer (every rotation would need a new installer on 4,000 PCs, and the installer is unsigned until CR-30-1's release signing); certificate pinning (breaks at every renewal). (3) **Outcomes, retention, instructions** (TWK-05): `outbox.acked_at` replaces the delete; a purge after `sync.outbox.retention_days` (a till setting, default 7, overwritten from the snapshot's `config` table); a local `anomaly` table takes every QUARANTINED outcome, the status bar shows the unseen count and the Z-report prints "N facts refused by central, see the office", the receipt staying as issued (a quarantined sale is still a sale on paper and in the drawer); `RESEND_FROM(seq)` clears `acked_at` for retained rows and records an anomaly when the oldest needed row is gone; `FLOOR_NOTICE` is a supervisor banner; `409 sync.sequence_gap` resends from `expected_seq` when retained, else anomaly and stop; a `403` revoke is honoured only when its Ed25519 signature verifies with the enrolled key, names this device and post-dates the enrolment, and then the till locks, deletes the snapshot rows and **keeps** `setting`, `receipt`, `till_session` and `outbox`. **D-3**: a revoked till resumes uploading its kept outbox from `last acknowledged + 1` when the administrator reinstates the device or issues a new enrolment code for the same device id (the cursor at central is unchanged); a device never reinstated has its unreceived numbers recorded as a documented gap by counter transfer (doc 32 section 8). FLAGGED has no channel to the till and is noted as a deviation in `till/README.md`. (4) **Durability and sign-in**: `synchronous=FULL` on the encrypted database and a start-up repair that moves `NEXT_RECEIPT_NUMBER` and `NEXT_DEVICE_SEQ` above any stored row, writing an anomaly (TWK-06); the PIN counter and lock-out persist in `setting` in the failure's transaction, per till not per operator, with an `audit.*` fact to the outbox (26A section 8: "local + audit") (TWK-03); Argon2 parameters from the PHC string are bounded (memory 8 MB to 1 GB, iterations 1 to 100, parallelism 1 to 16) and an unreadable hash is "this operator's PIN record cannot be read; ask the office", which does not count as a wrong PIN (TWK-10); the key file is written to a temporary name and moved atomically, an existing `till.db` with no key fails with "the office must re-enrol this PC" instead of a silent new key, an empty or short key file is corrupt, and the DPAPI call takes an application constant as entropy (TWK-08; doc 32 section 8 already covers a lost outbox: quarantine, ALERT, audited sequence reset). (5) **The trial cashier is an explicit opt-in** (TWK-04): `COOP_TILL_TRIAL_CASHIER=true` (written by `devEnrolmentCode` into `enrol-prefill.properties`), off by default, and refused once the snapshot has ever carried an operator row (`operators_seen`); no field in the sync contract, no second build. (6) **The clock** (TWK-07, D-4): the offset is refreshed from every heartbeat as well as every ack; the raw clock reading is stored beside it and a reading that goes backwards or jumps more than a bound drops the offset with an anomaly until the next heartbeat; an offset over 7 days is refused; a **supervisor may move the till's business date backwards when no session is open**, issued receipts and sessions keeping the date they carry (the till's date is a cache of central's forward-only business date, doc 26 section 3.5, not that date itself), and the till refuses to open a business date more than one day after central's last `server_time` when it synced within 48 hours. Rejected: forward-only for ever (a wrong clock would misdate every later receipt). (7) The till gzips its batches (doc 32 section 3.2 says "everything is gzip-compressed"; no CR); the heartbeat may stay plain.
