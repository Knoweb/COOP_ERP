- **A synthetic batch is recognised by its number's shape, not by a `synthetic` flag from the server (28 Sep, branch `fix/sinhala-dates-and-batch-labels`):** `GrnLineResponse` (m4trading) and `LotBalanceResponse` (m5inventory) carry no field saying a batch is synthetic; adding one is an API slice change (contract test, `gen-clients`, both query implementations) beyond a web-only fix. The screens instead match the backend's own fixed shape, `S-<document>-<line>` (`BatchGuards.syntheticBatchNo`, M2-05), with `isSyntheticBatchNo` in `tradingView.ts`/`stockView.ts`. This is exact for every batch M2 has invented (the format is fixed and never chosen by a supplier through the normal batch-number field), but it means a supplier-printed batch number that happened to match `S-<anything>-<digits>` would also be hidden; nothing in the current seed or demo data does. For the architect: add `synthetic: boolean` to `GrnLineResponse` and `LotBalanceResponse` (and `DeliveryLineResponse` once it carries a batch number) so the screen reads the batch record's own flag instead of pattern-matching it.
