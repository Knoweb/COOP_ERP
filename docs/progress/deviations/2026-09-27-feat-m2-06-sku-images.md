The kernel gained `kernel.api.ObjectStorage` (presign, verify, bounded read, write, read URL under the same register limits) and `JobExecution.ownScopeOf` / `federationView`; M2's ThumbnailJob is the verifier hook. Raised as `docs/change-requests/CR-19A-7.md`, built first with no kernel row (M2 kept the K-09 rules on its own row), then accepted as revised on 27 September on the architect's delegation (branch `fix/cr-19a-7-object-ledger`): the kernel keeps an upload ledger, `kernel.object_upload` (kernel V0060), and enforces the K-09 rules there for every module (settle only after the presign window, settled rows immutable, no new URL after settle, limits on what is derived, nothing read from an unverified object, the key's entity and module the caller's); M2 keeps its own window guard as well. `JobExecution.ownScopeOf` stays, its risk documented, callable from a `@ScheduledJob` method only (ArchUnit). The thumbnail is not doc 22's WebP (plain Java: the JDK writes no WebP): PNG as first built, a JPEG within doc 22's 10 KB since the decision of 27 September (CR-22A-2, branch `feat/decisions-m2-catalogue`).
