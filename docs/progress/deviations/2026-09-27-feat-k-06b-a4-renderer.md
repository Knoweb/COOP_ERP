- **The A4 renderer drives the Chromium command line, not Playwright, versus 19A section 6 and PLAN_TO_M2 6.13 (27 Sep, branch `feat/k-06b-a4-renderer`; decided on the architect's delegation):** `ChromiumPdf` runs `chromium --headless --print-to-pdf` on a page written to a directory of its own, with a profile of its own, and kills it past `report.render.timeout_seconds`. Reason: Playwright for Java ships a Node driver for every platform inside its jar and downloads its own browsers at run time, which is a second runtime and a download in a worker image that must carry a pinned browser anyway; the command line gives the same Chromium, and so the same HarfBuzz shaping that 19A chose it for, with no library at all. Printing one page is all the renderer asks of the browser. Chromium runs with `--no-sandbox` because its sandbox needs kernel features a container does not grant to an unprivileged user; what it opens is the kernel's own page, under a content security policy that loads nothing from outside it. Revisit with Playwright if a template ever needs scripted interaction before printing.
