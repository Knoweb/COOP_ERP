- **The deployment kit of wave 2 (PR 15 of `docs/reviews/wave2-fix-plan.md`), built with these differences from `2026-10-06-wave2-deploy-kit.md` and the plan (6 Oct, branch `fix/wave2-15-deploy-kit`):** (1) **Fonts**: the sign-in page ships the web client's own fonts (Noto Sans, Noto Sans Sinhala, Noto Sans Tamil, weights 400 and 600, from `@fontsource`, OFL) under `resources/fonts/`, not Inter: Inter has no Sinhala or Tamil letters, is in no file of the repository, and the fix review asked to "reuse the files the web client already embeds". (2) **`CONFIGURE_TOTP` and the default roles** are set in the running demo realm by `apply_realm_policy` (kcadm, on every bootstrap, deploy, restore and reset), not in `infra/compose/realm-dev.json`: that file is also the laptop's realm and the integration tests' (`KeycloakAdminClientIntegrationTest` sets `CONFIGURE_TOTP` on a user after an M1 second-factor reset), and a `default-roles-coop` definition in the file stops Keycloak 26.7's import ("Unable to find composite realm role: uma_authorization", found on the local kit). `realm-dev.json` is unchanged: brute-force protection there locked `fed-admin` out in CI's end-to-end run (four browsers signing the same users in at once trip Keycloak's quick-login check), so `render_realm` adds it to the demo server's rendered realm instead (temporary lockout, 30 failures, at most 15 minutes) and `apply_realm_policy` to the running one. (3) **`restore.sh` starts the version that made the backup** (the stamp's `<stamp>.tag` becomes `IMAGE_TAG`), instead of only refusing an older image: so it can never start an image older than the dump, and the decided rollback (`restore.sh <stamp>`, `git checkout <previous>`, `deploy.sh`) never runs the newer backend on the restored database first (it would migrate it forward again). A backup without a tag file needs `--use-current-image`. (3a) **The uploaded files are not copied with `mc mirror`** (the decision's tool): an M2 image's key `<id>` is also the prefix of its thumbnail's `<id>/thumb.jpg`, a file system cannot hold a file and a folder of one name, and the mirror skipped the thumbnail without an error (found by the restore drill on the local kit). MinIO's own listing also hides `<id>/thumb.jpg` while `<id>` exists, and `mc cp` back to `<id>` writes into `<id>/` when the thumbnail is there. `infra/deploy/objects.sh` (run in the MinIO client container) lists each key's own prefix as well, stores each object as a file named by the hash of its key, with an `INDEX` of hash, content type and key, copies only what the backup does not hold yet, and puts every object back with `mc put` (the exact key, its content type). The M2 key layout itself (a thumbnail under its original's key) is worth a look by M2: any later tool that lists the bucket meets the same trap. (3b) **The console through the tunnel** needs one more setting than `KC_HOSTNAME_ADMIN`: the master realm's sign-in form still posted to the public address (404 at Caddy), found on the local kit; `apply_realm_policy` sets the master realm's `frontendUrl` to `KC_HOSTNAME_ADMIN`, after which the console signs in at `http://localhost:8081/auth/admin/`. (4) **The backend's MinIO user** may also delete objects in `attachments`, `images` and `packages` (the clean-up of failed uploads deletes, `S3ObjectStore.delete`); it has no delete in `audit-anchors` and no bucket rights. (5) **`demo-data.sh --repair-users`** repairs the users of the realm file (the storyline's characters), not users a tester made in the back office. (6) The theme lives in `infra/keycloak/theme/coop` (the plan wrote `themes/`). (7) `COOP_ERP_MFA_PASSWORD_REAUTH_PUBLIC_ACK=demo-data-only` is set in `infra/deploy/compose.yml` as the plan says; the kernel property that reads it comes with PR 03, and until then the variable is ignored. (8) The temporary-password page (phase 4) is Keycloak's parent template and stays English in Sinhala and Tamil, the known gap the decision allows. (9) Not built, as decided: the docker-only publish job and signed provenance (doc 35), `read_only` roots, the management-port split, encrypted dumps and PITR (before real data).
