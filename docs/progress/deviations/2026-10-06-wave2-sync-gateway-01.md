- **Where the till sync gateway fix departs from the plan's letter (6 Oct, branch `fix/till-sync-gateway-validation`, plan PR 03):** (1) the four-column UPDATE grant on `kernel.sync_quarantine` is `resolved_at`, `resolved_by_user_id`, `resolution`, `resolution_reason`; `raw_event` is not granted to `app_rw` and is nulled only by the `SECURITY DEFINER` function `kernel.sync_quarantine_drop_raw` (run by the nightly job in the federation-wide scope, as `change_log_purge` is), because the job spans every entity and least privilege keeps the application from rewriting a fact's raw text; (2) `observeDeviceNumber` treats a series as the device's own when the device is its holder and it is at the device's shop; "or this till position" is covered by the holder change that moves the counter with the position (the kernel does not read M1's position in the caller's transaction); the `NUMBER_JUMP` limit stays M6's (`pos.series.max_jump`, PR 13), which the outcome's `nextNumberBefore` serves; (3) the decimal rule is "text of plain digits" as `Facts.kt` writes it, so the conformance fixture that sent JSON numbers now sends text; (4) the `ack` variable of the #184 shortcut is set in `infra/deploy/compose.yml` here, not only in PR 15, so that the demo server still starts on any commit after this one; (5) the snapshot and change-log floor check reads the version the device last reported (heartbeat or batch, the higher), since those calls carry none; (6) `sync.quarantine.resolve` is added to the Entity Administrator role template so an MPCS administrator can hold it on a new database (the seed loader does not add it to existing roles).
