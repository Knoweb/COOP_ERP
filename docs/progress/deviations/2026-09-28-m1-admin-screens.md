- **M1 administration screens leave out role editing and reactivation (28 Sep, branch `feat/m1-admin-screens`; accepted on the architect's delegation):** the roles screen reads the catalogue only; the slice can create, amend and retire a role, but a usable editor needs a readable permission catalogue (codes with descriptions in three languages) that the slice does not serve, so role editing waits for that read (M1-08). A deactivated user is not reactivated: 21A M1-07 makes deactivation final and the slice has no reactivate; the successor is a new user (`succeedsUserId`). Where a user works is not a field of the user but the location of each role assignment (`user_role.scope_location_id`), so the New user form has no locations and the card assigns a role entity-wide or at one location. The reason of a revoked role or grant is sent as the chosen code, with the typed text after it, because those two requests take one free-text `reason` and not the code and text of `UserReasonRequest`.
