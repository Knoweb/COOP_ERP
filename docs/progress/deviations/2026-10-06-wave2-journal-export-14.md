- **The journal export, the counterparty delivery and SMTP as built (wave 2, branch `fix/m9-export-provisional-and-counterparty-delivery`), the closest safe build of `2026-10-06-wave2-journal-export.md` (1), (3), (4), `2026-10-06-wave2-buyer-postings.md` (2) and `2026-10-06-wave2-notifications.md` (3):** (1) The "supplement due" signal is its own read, `GET /v1/integration/journal-postings/supplement-due` (`int.journal.read`), not a field on the exports list: that list is a bare JSON array of exports, and an entity-level figure does not belong on each row; the page shows it as the banner the decision asks for. (2) The version-2 file marks every entry with an `export` column, `FINAL` or `PROVISIONAL`, rather than a comment line or a header note: a CSV import has no comments, and the accountant sees the mark in the package and can filter on it. (3) The counterparty consumer records the side opposite to the document type's issuer role (BUYER for INV and CN, which is all that is published today), not "BUYER lines" by name, so a GRN event (issuer BUYER) delivered to a counterparty would record SELLER lines, never the receiver's own; and M4 names no counterparty on a GRN or a PRC event, since those carry the owner's side only, so the kernel delivers them to nobody else. An event whose payload names a counterparty but no document, a document that does not exist, or a counterparty that is not the document's is poison (dead-lettered with the reason, never retried); an event with no counterparty is passed over as applied, so a replay of events published before the field existed does not dead-letter them all. (4) "A non-local host" for the SMTP start-up rule means a host name with a dot that is not a loopback address, a `.localhost` or a `.test` name: a bare service name such as the compose stack's `mailpit` resolves only on the deployment's own network and is let through, so the demo server (its issuer is not a development one) keeps starting with Mailpit and `security = NONE`. The three variables are in `infra/deploy/.env.example`; passing them into the container in `infra/deploy/compose.yml` is PR 15's file and is left to it. (5) `BuyerJournalPostingsConsumer` is a consumer of one type (`journal.postings_ready.v1`), not of every type: a counterparty consumer reads `documentId` and `counterpartyEntityId` from the payload, which the envelope form of `"*"` does not give it, and the registry refuses the combination.
