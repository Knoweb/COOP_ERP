- **CR-30-1 desktop trial, built differently from the research report and the design (29 Sep, branch `feat/till-desktop-trial`):** (1) **Prices**: central's snapshot has no price table yet (doc 32 section 5.1; no M3 contributor), so the till reads a `price` table when one comes, then a local price book (`prices.csv`, written by the `devEnrolmentCode` helper from the society's published shelf list or the demo catalogue's printed MRPs), else the cashier keys the price. (2) **Trial cashier**: the demo stack has no till user with a PIN, so the snapshot's operator table is empty and the till offers a cashier with a fixed id per till, as the backend's till simulator does; the PIN path (Argon2id, five failures lock fifteen minutes) is built and unit-tested only. (3) **No `security` module** (CR-30-1 lists one): the `KeyVault` port is in core, the DPAPI and mode-600-file vaults in `desktop`, Ed25519 and Argon2id in `sync`'s jvmMain. (4) **The database key is used raw** (256 random bits; no SQLCipher PBKDF2, which cost about 2 s per start). (5) **Screens use the OS's fonts**; the bundled Noto fonts are for the paper only (Linux needs `fonts-noto-core`). (6) **Room is removed** from the Android app; persistence is SQLDelight in `db`, as CR-30-1 says. (7) Newer versions than the report's table (Kotlin 2.3.21, CMP 1.11.1, AGP 8.13.2, Gradle 8.14.4); Hydraulic Conveyor not evaluated. (8) **Found in central**: M6 applies `receipt.issued.v1` and `till_session.opened.v1` in two consumers, so a receipt uploaded in the same batch as its session can be applied first and flagged `SESSION_UNKNOWN` (seen once in three sales against the local stack); the till cannot prevent it. Raised in the pull request, not fixed here.
