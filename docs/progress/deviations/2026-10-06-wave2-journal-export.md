- **The journal export's four guarantees (wave 2: M9-03, M9-05), decided on the architect's delegation (6 Oct, branch `docs/wave2-decisions`), CR-29-1:** an accountant needs (a) a file for a closed period that is complete when generated or says plainly that it is not, (b) each posting exported exactly once, (c) what arrives late flagged and fetchable as a supplement, (d) a file downloadable again byte for byte with the hash that proves it. (1) **D2: the generated bytes are stored** in `integration.journal_export_file (export_id PK, format_version, content bytea, content_hash, owner_entity_id)`, insert-only, four-class policies, written in the export's own transaction (m9integration V0006); `RequestJournalExport` builds the bytes once and hashes them; `file()` serves the stored bytes; `reconciliation()` checks the stored hash and regenerates with the writer of the recorded `format_version`; exports made before V0006 are served by `JournalFileV1`, frozen with a comment that it never changes. This amends README deviation 2 ("rebuilt on download"). Rejected: a format version with frozen writers alone (one careless edit breaks every past hash); object storage now (not transactional; the kernel has no server-side put; it can replace the bytea later by CR if volume ever asks). (2) **D1: an open period is refused unless the export says it is provisional.** `periodTo >= today` in `coop-erp.business-timezone` answers `m9.journal.period_open` unless the request carries `provisional: true` (additive on the command and the slice; 29A section 5 already lists it); a provisional export takes its postings once, like any other, and is marked PROVISIONAL in the list, the file name (`journal_..._PROVISIONAL.csv`) and the version-2 file; the audit `after` and `JournalExportGenerated` carry the flag; what arrives later for its period is a **supplement, never a superseding re-export**. When location-dated postings reach M9 (the buyer's GRN, M5 WOF/ADJ), "closed" extends to every location of the entity having `BusinessDate.current(location) > periodTo`, which needs `m1party::query` in M9's allowed dependencies; a TODO cites this decision. (3) **A "supplement due" signal**: a query and a field on the exports list giving the unexported postings dated on or before the latest `period_to` the entity has exported (count, amount, earliest and latest date); the page shows the banner. (4) Web: the default period ends yesterday; the provisional box is ticked and required when the end date is today or later; the demo script that exports "to today" passes the flag. Rejected: doc 29's "superseded later" (the accountant would have to reverse an imported file in the package, and the posting-once index would need rework); refusing open periods outright (breaks the same-day demo export and month-to-date reviews); marking without refusing (the default action would make provisional files silently). Open, for the architect when M5/M6 postings reach M9: whether one shop offline for two days (doc 32 allows it) should block the entity's final export; the provisional flag is the escape either way.
