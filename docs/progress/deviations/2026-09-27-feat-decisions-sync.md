- **The sequence reset is an operation of the sync slice and moves forward only, versus doc 32 section 8 (27 Sep, branch `feat/decisions-sync`):** 19A section 8 lists no endpoint for it; it is `POST /v1/sync/devices/{device_id}/sequence-reset` beside the enrolment code, an administrator's call with `sys.device.enrol` (the permission of the enrolment workflow; `sys.device.manage` stays unused for the catalogue freeze, as for the code). Doc 32 says "sets the cursor to the device's new start"; a new start at or below the cursor is refused (`sync.sequence_reset.not_forward`): going back would answer the device's new events as duplicates of the old ones at the same numbers, and a till that restarted from 1 is enrolled again, which hands it the next sequence central expects. The recorded gap is of device sequences (D-I4), not of document numbers; a document-number gap is still the gap check's.
