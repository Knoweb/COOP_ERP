- **Kernel defaults, read checks and sync limits (wave 2: TWK-19, TWK-24, TWK-25, TWK-27, TWK-28, TWK-29), decided on the architect's delegation (6 Oct, branch `docs/wave2-decisions`):** (1) **Fail closed by default**: `coop-erp.security.enforce-permissions` defaults to `true` (the module integration tests that run as users of their own set `false` in their profile; a forgotten environment variable must not open the server) (TWK-29); `coop-erp.sync.signing.required` defaults to `true` and a blank signing key stops the start with the property names in the message, `false` only in the test resources (TWK-27). (2) **HEAD is GET** for the read-permission interceptor (Spring serves HEAD from a GET mapping); a contract test sends HEAD to one GET path per slice without the permission and expects 403; OPTIONS is CORS's and is left alone (TWK-19). (3) **Every sync body is bounded and counted** (TWK-24): `GzipRequestFilter` becomes `SyncBodyFilter` for every body under `/v1/sync/`, reading at most `limit + 1` bytes, the limit `sync.batch.max_bytes` (DR-1, 2 MB compressed) for a gzip body and the new property `coop-erp.sync.max-uncompressed-bytes` (default 16 MB, about a JSON batch's inflation) for a plain one, chunked or not; `WIRE_BYTES` is the bytes read, so `wireBytes()` always finds it; plain bodies stay accepted (refusing them would break the till on the day the fix lands) and the till gzips in its own PR; Caddy's `request_body max_size 8MB` on `/api/*` is the edge's second line. (4) **A per-device request bucket** (`sync.rate.requests_per_minute`, register key, default 30) on `getSnapshot`, `listChanges`, `heartbeat` and `presignAttachment`, beside the batch and byte buckets, and a snapshot's answer costs its bytes against the hourly byte bucket (TWK-25); the pre-built full snapshot per (location, version) in object storage stays **K-08-F2** with its recorded trigger (27 Sep); no in-memory cache as a stop-gap (it would be undone). (5) **Rendering**: a `Semaphore` sized by `render.max_concurrent` (register, default 2) around Chromium with a `render.busy` problem when it cannot be had within a bound; `--no-sandbox` stays (the SUID sandbox does not work in an unprivileged container) with the template lint (`th:utext`, `[(`) over `templates/**` as the compensating control, and the worker image runs Chromium as a non-root user under the default seccomp profile; the document-id predicate on `presignGetOfParty` waits for a third caller, pinned meanwhile by an ArchUnit rule that only M4 and M8 call it (TWK-28). (6) **Kernel migration numbers**: `V0084` sync quarantine resolution, `V0085` notification log (keyed hash, recipient entity and role, legacy replacement), `V0086` definer hygiene and `document_open_for_write`; later kernel migrations continue upward, never a lane number again.
