- **An internal command, versus 19A section 3 and 17A R7 (27 Sep, branch `feat/m2-05-batches`):** RegisterBatch has no operation and its permission is the caller module's (doc 22 section 4.1; 22A section 4: "exported for M4/M5"), which no rule of the kernel allowed: every handler needed an x-permission, and the interceptor would have claimed the calling request's idempotency key a second time. `CommandHandler.INTERNAL` marks such a handler; the interceptor passes it without a permission check or an idempotency claim; `check-permissions.mjs` skips it. Raised as `docs/change-requests/CR-19A-6.md`; built to its proposal. **Corrected 27 Sep (branch `fix/cr-19a-6-guard-rails`):** the "requires the caller's transaction" test this entry named never fired (the handler's own `@Transactional` is the outer advice, so a transaction is always active), and a controller or job calling `BatchRegistration` got no permission check and no idempotency; the interceptor now requires a running outer command instead, and the build refuses a public path to an internal command (the Done entry "CR-19A-6 guard rails", pull request #138). CR-19A-6 is accepted with those guard rails.
