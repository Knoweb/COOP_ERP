## Deviations

- **Extracts** are produced with `pdftotext -layout -enc UTF-8 -eol unix`, not bare `-layout`: on Windows the bare form wrote Latin-1 with every dash as an invalid UTF-8 byte.
- **Existing skeleton versus 17A**, to resolve in Step 2: Gradle 9.7.1 wrapper where 17A says 8.10+; no `gradle/libs.versions.toml`; the project is named coop-erp by decision of 18 Sep (17A says knoweb); Spring Boot 3.3.5 and Modulith 1.2.5 pinned inline; no JPA, Security, Testcontainers, OpenAPI generator or Jib; Flyway runs from a `@PostConstruct` in `FlywayConfig`; `ArchitectureTests` lacks 17A's layer rule and own-schema repository rule and has an extra kernel-internals rule; the three `i18n` files are empty; no Makefile, hello module, shared engine, web or till scaffold, compose, CI workflow or `make new-module`.
- **AGENTS.md** lists nine module packages; 17A §2 and the repository also carry `m10procurement` as a reserved package.
- **Build machine** used for this session has no JDK, Docker, Node or make on PATH, so the Checkpoint 2 proof cannot run on it as it stands.
- **Document set:** the register lists two supporting documents (Document_Numbering_RFC, Numbering_Scheme_Tax_Advisor_Briefing) that are in neither the Drive baseline folder nor the repository. Docs 34 to 40 are unwritten; ADR-37 to ADR-50 are not yet in doc 09; glossary 12 lacks the design terms; the Markdown-to-PDF render script has not been chosen.
- **S0-10 versus 17A §10:** the backend image is built by Jib as 17A says (`make image`, plugin 3.5.4 declared in the root build so all plugins share one Jackson version). One addition: `make image` pulls the base image with Docker and passes `-PjibFromDaemon=true`, so Jib reads the base from the local daemon; on a machine not signed in to Docker Hub, Docker Desktop hands Jib an empty credential and the registry answers 401. CI pushes with `./gradlew :app:jib` and leaves the flag off. Keycloak keeps no data volume, so `realm-dev.json` is re-imported whenever its container is recreated and console changes are not kept. The token claims `ent`, `cls`, `lang` and `roles` are provisional until K-02 defines the mapping of doc 19 §1 (`dev`, `scopes`, `rv`, `mfa_at` are absent); the two development entity ids (`0190f000-…-0001` Federation, `…-0002` an MPCS) are shared by the realm and the hello seed. `make test-int` fails on purpose until S0-12 brings integration tests. `.gitattributes` now forces LF for Makefile, Dockerfile, gradlew, YAML, conf and SQL files. Existing local databases created by the earlier compose file had no volume, so nothing needs migrating; after pulling this change run `make reset` once.
- **Build machine:** on this Windows machine every JVM failed to open a selector (`Unable to establish loopback connection`): Java creates a local socket file in the temp folder on C:, and that fails there. Cause not found; workaround is the user environment variable `JAVA_TOOL_OPTIONS=-Djdk.net.unixdomain.tmpdir=D:/tmp`, with which `./gradlew test` (32 tests) and `make up` pass. It is a machine setting, not a repository change.
- **S0-12 versus 17A §12:** listed with reasons in `hello/README.md`. In short: no `entityId` in the command (taken from the scope); the controller is hand-written against the slice until server-side generation exists (S0-06); the audit and event stubs still log, because `kernel.audit_event` and `kernel.event_outbox` belong to 19A K-04 and K-05, so the tests count calls, not rows; no `ext_view` policy until K-01; Testcontainers 1.21.4 overrides Boot's 1.19, which Docker Engine 29 refuses. Open proof rows: the till hello screen and till-side `Money.roundCash` parity (not built here, no Android SDK on the build machine) and the two-instance Playwright run (needs login, S0-07). The in-memory idempotency store holds for one instance only, until K-03.
- **S0-13 versus 17A:** `make new-module` takes a third argument, `ENTITY` (17A §13 shows `NAME` and `SCHEMA`): without it every table, class and URL of the copy would be named after the schema (`catalogue.catalogue`), and two modules could not coexist because Spring names beans after classes. One lowercase word only; compound names are renamed by hand. The copy's permission strings (`<schema>.<entity>.register`) are placeholders, because the guides use short codes that cannot be derived (`cat.sku.create`); the README written into the new module lists this first. `m10procurement` cannot be scaffolded: it has no schema in doc 18 Part F, `FlywayConfig` or the architecture tests. The till screen is not scaffolded, because hello has none yet.
